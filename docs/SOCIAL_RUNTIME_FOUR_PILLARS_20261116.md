# 拟人化社交媒体运行时：并行线程 × 共享语义 × 选择性注意 × 受众边界

**日期**：2026-11-16
**适用**：`astrbot_plugin_private_companion` 7.1.x（`companion_v2`）
**结论先行**：这四件事不是四个功能，而是同一个「社会性运行时」的四条约束。分开做，任何一条都会露馅；
合起来做，才有"一个人同时在生活、在回消息、在发空间"的感觉。

> 实施说明：下文的“现状”和“已知裂缝”记录的是动工前的 7.1.20 基线；本轮 P0–P4 的落地情况见第十三节。

---

## 一、为什么是这四个

真人在社交媒体上的行为，受四种约束同时作用：

| 约束 | 真人的表现 | 系统里对应 |
| --- | --- | --- |
| **时间/并发** | 同时和几个人聊、群里潜水、空间发动态，各条线进度不同 | 并行线程 |
| **认知一致性** | 同一件事在不同地方说法一致；记得住人和事的"意义" | 共享语义 |
| **资源稀缺** | 不是每条消息都回；会已读不回、会晚回、会漏看 | 选择性注意 |
| **社会规范** | 什么话对谁说、什么话不能说给谁听 | 受众边界 |

反过来说，只做其中一个会得到非常典型的"假人"：

- 只做线程、不做共享语义 → **人格分裂**：私聊里说"我今天在家"，群里说"我刚下班"。
- 只做共享语义、不做受众边界 → **泄密**：把私聊里的秘密带到群里，或反过来。
- 只做受众边界、不做共享语义 → **空洞**：每个场合都是一套正确但互不相干的台词。
- 只做选择性注意、不做其余三个 → **忽冷忽热**：不是"有选择"，是"随机不回"。

所以正确的建设顺序是 **L0 共享语义 → L1 线程 → L2 注意力 → L3 受众投影**，
其中 L2 和 L3 都只是 L0/L1 上的**视图与闸门**，不另存一份事实。

---

## 二、目标架构

```
                 ┌──────────────────────────────────────────────┐
  L3 受众投影     │ 每个受众一份"可说什么/可知道什么"的投影      │
                 │ private=后台  group=前台  qzone=广播          │
                 └──────────────────────────────────────────────┘
                                   ▲
                 ┌──────────────────────────────────────────────┐
  L2 注意力       │ 显著性打分 → 现在回 / 稍后回 / 只看不回 /      │
                 │ 只记不说 / 忽略；全局与单线程预算             │
                 └──────────────────────────────────────────────┘
                                   ▲
                 ┌──────────────────────────────────────────────┐
  L1 线程         │ social_threads：一条关系线一个状态            │
                 │ 参与者、话题、欠回复、未完事项、情绪余温       │
                 └──────────────────────────────────────────────┘
                                   ▲
                 ┌──────────────────────────────────────────────┐
  L0 共享语义     │ 一个"我"：角色生活、心情、时间线、关系账本、   │
                 │ 事实与事件（带证据时间、来源、可见性）         │
                 └──────────────────────────────────────────────┘
```

数据流（一条消息进来）：

```
入站事件
  → 归属到线程（L1：这是哪条关系线？）
  → 显著性评分（L2：现在要不要理？）
  → 检索共享语义（L0：关于这个人/这件事我知道什么？）
  → 受众投影（L3：这些里哪些能在这个场合说？）
  → 表达（语气、长度、延迟、是否主动）
  → 回写（L0 记事实/事件，L1 更新线程状态，L2 记注意力账）
```

关键原则：**下游只做投影和闸门，不产生第二份真相。**

## 三、L0 共享语义：一个"我"，不是三套记忆

### 3.1 现状（已核实）

系统里其实已经有三层知识，但彼此不通：

| 层 | 表/模块 | 归属 | 用途 |
| --- | --- | --- | --- |
| 角色生活 | `role_work/life`、`role_work/state`、`role_work/timeline`、`role_work/journal` | 角色级 | 日程、心情、身体、日记、时间线 |
| 私人事实 | `memory_atoms`（`owner_key` 含 actor + `"private"`，`companion_v2/memory/models.py:145`） | 每个"角色×用户" | 对某个人的长期事实 |
| 群内陈述 | `memory/group/*`（`group_owner_key`，`memory/group/access.py:22`） | 每个"角色×群" | 群公共记忆、黑话、群事件 |

这带来两个直接后果：

1. **私人事实只能在私聊用**：`Proposal.visibility` 只允许 `"private"`（`memory/models.py:97-98`），
   群聊和空间拿不到任何"关于这个人"的事实。
2. **群里的公共事件回不到私聊**：同一个人先在群里说了件事，私聊里角色不会知道——
   除非他当时在场并单独记了一遍。

### 3.2 目标

一个**事实/事件图**，多份**视图**：

```
实体（人/群/地点/事物）
  ├─ 事实（semantic）：稳定、可验证、带有效期
  ├─ 事件（episodic）：某时某地发生了什么，带参与者
  └─ 关系（relational）：我和这个人/这个群现在是什么状态
```

每个节点都带：`occurred_at`（发生时间，不是写入时间）、`source`（证据）、`confidence`、
`valid_from/valid_to`、`visibility`、`origin_thread`。

### 3.3 必须补的三件事

**(a) 发生时间实体化。** `memory_atoms` 目前没有 `created_at`，列表排序只能用
`record_json` 里的 `json_extract`（报告第十二节）。加一列并建索引：

```sql
ALTER TABLE memory_atoms ADD COLUMN occurred_at TEXT;
CREATE INDEX memory_atoms_occurred_idx
  ON memory_atoms(owner_key, occurred_at DESC, atom_id DESC);
```

写入时从 `proposal.evidence[0].source.issued_at` 提取；读不到就回落到 `observed_at`。
排序/游标一律用它，**不要用 hash 当顺序键**（`atom_id` 是 sha256 前缀）。

**(b) 可见性分级。** 把 `visibility` 从"只有 private"扩成四档：

| 级别 | 含义 | 典型来源 |
| --- | --- | --- |
| `private_pair` | 只对"这个角色×这个人"可见 | 私聊里的个人信息 |
| `shareable` | 当事人同意后可跨场合转述（可匿名化） | "你可以跟别人说我在学吉他" |
| `group_public` | 该群内公开 | 群里说过的话、群事件 |
| `public` | 广播（空间） | 角色自己的生活、公开作品 |

注意：`legacy_materials.py` 里 V1 本来就有 `private_pair` / `shareable` / `group_public`
（`memory/legacy_materials.py:35-36`），V2 把它们丢了。这不是新发明，是把旧语义补回来，
并且这次要带**当事人授权**（谁在什么场合允许转述）。

**(c) 写入要过"注意力"闸门。** 现在的反思链是"有材料就抽"，
报告里 381 条事实背后是 445 个批次、93 个放弃批次、58 万条假性剩余来源。
真人不会把每句话都变成一条事实。抽取前先算显著性（见 L2），
只让"新信息、与人相关、稳定、有情绪重量"的材料进入反思。

### 3.4 读取

检索按 `audience × relevance × recency` 三轴过滤：

```
recall(thread, query):
  candidates = facts/episodes where visibility allows thread.audience
  rank by (relevance, recency_decay, confidence, relationship_weight)
  return top-k with provenance
```

`memory/context.py` 现在是"private 才给语义记忆"（`memory/context.py:177-178`），
扩成按 `visibility` 判定，而不是按 `scope.kind` 一刀切。

## 四、L1 并行线程：一条关系线一个状态

### 4.1 线程是什么

线程不是传输层的 session，也不是一次对话窗口，而是**一段持续的关系线**：

```
thread = (角色, 受众, 参与者集合, 话题, 未完成事项)
```

同一个人可以在私聊、群、空间三条线上同时存在；同一个群里可以有多条并行的"话题线"
（一群人在聊游戏，两个人在聊昨天的事）。

### 4.2 数据模型

```sql
CREATE TABLE social_threads (
  thread_id       TEXT PRIMARY KEY,
  owner_key       TEXT NOT NULL,        -- 角色级，不是用户级
  kind            TEXT NOT NULL,        -- private | group | qzone | ...
  scope_key       TEXT NOT NULL,
  participants_json TEXT NOT NULL,      -- 参与者（人/群）
  topic           TEXT NOT NULL DEFAULT '',
  state           TEXT NOT NULL,        -- active | idle | dormant | archived
  last_event_at   TEXT NOT NULL,
  last_reply_at   TEXT NOT NULL DEFAULT '',
  owed_reply      INTEGER NOT NULL DEFAULT 0,
  attention_json  TEXT NOT NULL,        -- 显著性、情绪余温、未完事项
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);
```

`owner_key` 必须是**角色级**（installation + bot + role），不能带 actor——
线程属于"这个人格的生活"，不属于某个用户。

### 4.3 每条线程的工作集

线程不加载全部记忆，只带四样东西：

1. 最近 N 轮对话（原文，按时间）
2. 未完事项（`agenda` 里挂在这条线上的 open items）
3. 钉住的事实（pinned，最多几条）
4. 未解决的疑问（"他上次说的那个考试，后来怎么样了"）

这四样构成"我此刻记得的关于这条线的事"，其余靠 L0 检索。

### 4.4 现状与差距

已存在：`conversation/flow.py` 的按 scope 批处理、`agenda` 的 open items、
`proactive` 的按联系人调度、`conversation/group_observation.py` 里临时的 thread 聚合。

缺的是：

- **没有持久线程实体**：群聊里的"话题线"只在观察模块里临时算，不落库、不跨轮。
- **没有跨线程状态**：私聊里答应的事，群里不会提；群里发生的事，私聊不知道。
- **没有欠回复账**：谁在等我、等多久，系统没有这个概念。

### 4.5 线程调度

多条线程同时 active 时，调度器按"欠回复 + 显著性 + 等待时长"排序，
并且要有**公平性**：不能因为私聊一直有新消息，就让群里的线饿死。

## 五、L2 选择性注意：不是每条都回

### 5.1 显著性

```
score = 0.30 * addressed      # 是否点名/直接提问
      + 0.20 * question       # 是否在等一个回答
      + 0.15 * stake          # 与这段关系的利害（纪念日、冲突、求助）
      + 0.15 * novelty        # 新信息量
      + 0.10 * emotion        # 情绪强度
      + 0.10 * reciprocity    # 对方最近是否也在回应我
      - 0.25 * interruption   # 打断成本（我正在忙/在睡/在别的线）
      - 0.20 * recent_load    # 最近已占用多少注意力
```

四档动作：

| 动作 | 含义 | 现状对应 |
| --- | --- | --- |
| `respond_now` | 现在回 | 默认路径 |
| `defer` | 稍后回（有明确 due） | `busy_gate` 的延迟、群 debounce |
| `observe` | 看了，不回，但记住 | **没有** |
| `remember_only` | 不进对话，只进记忆 | **没有** |
| `ignore` | 完全不理 | 群回复准入的部分拒绝 |

`observe` 是关键：真人大量时间在"看但不说话"。没有这个状态，
系统要么全回（累、假），要么不回（冷、断）。

### 5.2 预算

- 单线程：每小时主动条数、连续追问上限（不许夺命连环 call）
- 全局：每天主动发起次数、同时 active 线程数
- 记忆：每天反思批次数、单批材料上限、修复链深度上限（3-5 层，不是 20）

### 5.3 注意力的两个作用面

1. **对话侧**：决定"回不回、何时回、回多长"。
2. **记忆侧**：决定"什么值得记"。两者共用同一个显著性函数，只是一个作用在输出，
   一个作用在写入。

现状是两套互不相干的启发式：`conversation/busy_gate.py`、`conversation/group_debounce.py`、
群回复准入、`proactive/budget.py`。它们各自正确，但没有一个统一的"我现在有多少注意力"。

## 六、L3 受众边界：前台与后台

### 6.1 三个场合

| 场合 | 戈夫曼 | 可见知识 | 语气 |
| --- | --- | --- | --- |
| 私聊 | 后台 | 私人事实、关系细节、角色生活 | 放松、具体、可脆弱 |
| 群聊 | 前台 | 群公共事实、角色生活（精选）、群体梗 | 有分寸、短、不独占 |
| 空间 | 广播 | 角色生活、公开作品、观点 | 最克制、可被所有人看到 |

### 6.2 投影矩阵

| 内容类型 | 私聊 | 群 | 空间 |
| --- | --- | --- | --- |
| 用户隐私事实 | 可见 | 禁止 | 禁止 |
| 群体公共事件 | 可引用（须在场） | 可见 | 禁止/匿名化 |
| 角色生活 | 可见 | 可见（精选） | 可见（精选） |
| 关系细节 | 可见 | 禁止 | 禁止 |
| 第三方信息 | 按授权 | 按授权 | 禁止 |

"可引用（须在场）"是最容易做错的一条：私聊里提到群里的事，
前提是**这个私聊对象当时也在那个群里**，否则就是跨场合泄密。

### 6.3 一致性

所有受众的说法，必须能由同一组 L0 事实 + 各自投影解释。
出现矛盾时，**在 L0 解决**（改事实/补证据），不是在表达层圆场。
这条是"像真人"和"像客服"的分水岭：客服可以每个渠道一套话术，人不行。

### 6.4 现状

安全隔离已经很强：`AudienceRef`、`SourceRecord.audience`、
`validate_reference_for_audience`、生成前的 audience 校验（`conversation/foreground.py:591-598`）。
但它是**安全边界**，不是**社会边界**：

- 只有"可见/不可见"两档，没有"可转述/可匿名/需授权"。
- 没有"这个受众知道什么"的模型。
- 空间（`qzone`）只有冷却、配额、去重（`qzone/policy.py`），没有受众投影。

## 八、实施前地基上的已知裂缝（与本副本核实）

动工前的工作副本是 7.1.20 的**未打补丁**状态，报告里的问题当时都能复现：

1. `memory/reflection_management.py:101` 的 `return` 之后有一段永远执行不到的孤儿代码
   （102-112 行），`enqueue` 实际不存在。

3. `memory/scheduling.py:279-282`：`incomplete` 时 `covered_until` 保持原值，每批从同一位置重扫。
4. `memory/management.py:99`：`ORDER BY atom_id`，而 `atom_id` 是 hash。
5. `execution/models.py:239`：`background_slots = 3`。
6. `pages/陪伴小屋/memory-page.js:639-640`：`abandoned` 被算进"待处理"。

这些不修，L0 的"共享语义"就是**脏的**：时间乱序、批次卡死、事实停更。
拟人化的前提是"记忆可信"，不是"记忆很多"。

## 十、评测指标

| 指标 | 目标 | 怎么量 |
| --- | --- | --- |
| 跨受众泄露率 | **0** | 构造私聊秘密，检查群/空间输出 |
| 矛盾率 | < 1% | 同一事实在不同线程的表述冲突 |
| 重复率 | 下降 | 主动消息/空间文案的 n-gram 重复 |
| 回复延迟分布 | 像人（对数正态、有在线时段） | 埋点 |
| 主动/被动比 | 有上限、有下限 | 按天统计 |
| 已读不回率 | 非零 | `observe` 状态占比 |
| 记忆精确率 | 上升 | 人工抽检事实是否正确 |
| 记忆召回率 | 上升 | 该记得的事是否记得 |
| 盲评"像人" | 上升 | 双盲对比 |

离线回放：用已记录的入站事件重放，比较不同注意力/投影策略的输出，
避免每次调参都上真机。

---

## 十一、反模式

1. **用 prompt 代替状态**：在系统提示里写"你要像真人一样"，不如把线程状态、注意力账、
   受众投影真正存下来。模型只能表演状态，不能维持状态。
2. **为拟人而拟人**：故意打错字、假装忘记、随机延迟——这些是表演，不是机制。
   真人的"不完美"来自资源约束和记忆衰减，不是脚本。
3. **全量记忆**：把每句话都抽成事实，等于没有记忆。选择性注意也要作用在写入侧。
4. **每个受众一套记忆**：碎片化，必然矛盾。一个 L0，多份投影。
5. **用随机数冒充节奏**：延迟要由"我在忙/我在睡/我在别的线"解释，不是 `random.uniform`。
6. **修复链无上限**：报告里 20 层修复链 + 93 个死批次就是教训。注意力也包括"什么时候放弃"。

---

## 十二、一句话版本

> 让角色有**一个持续的自己**（共享语义），**几条并行的关系线**（线程），
> **一份稀缺的注意力**（选择），和**一层分场合的自我呈现**（受众边界）；
> 其余的都只是这四件事的投影。
