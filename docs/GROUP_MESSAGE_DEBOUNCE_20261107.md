# 群聊连续消息防抖

普通群聊由 AstrBot 核心逐条生成回复，旧 V2 批次窗口不覆盖这条路径。原有连发提示只在后续消息的模型请求里生效，第一句未说完时仍可能先触发一轮回复。

核心入口现在按群目标和发言账号收集纯文本。首条开始 0.8–1.6 秒的自适应静默窗口；短句和未完句稍多等，完整长句少等。后续同一成员的文本刷新窗口，但从首条起最多等待 3 秒。最新原生事件保留消息身份，合并文本仅用于这一轮的候选判断和回复；先前事件不再单独唤醒核心模型。不同成员插话会结束旧窗口，不合并身份。

明确 @、宿主唤醒、引用、图片、语音、视频、文件及命令走原有即时路径。单轮最多合并 16 条、8000 字；达到预算时结束旧窗口，新消息独立处理，避免截断输入。旧片段在群聊参与提示中不重复当作历史唤醒，模型仍按完整意思自主决定回复或旁听。防抖只调整输入时序，不额外增加群聊回复硬闸门。

验证重点：同成员连发只做一次候选判断并使用最新消息身份；他人插话和非文本消息不串入批次；连续输入有总时限；合并后的提示词把片段视为一次表达。
