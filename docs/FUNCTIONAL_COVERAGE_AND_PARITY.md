# 陪伴体系功能覆盖与对等性设计

> 导航：[设计总纲](./FRAMEWORK_DESIGN.md) / [主题目录](./FRAMEWORK_DESIGN_INDEX.md)。定位：功能覆盖与验收设计；随领域切片复核用户能力，不单独规定全局顺序。

> 状态：设计稿。本文用于防止新框架在重建过程中只迁移“主链”，却遗漏旧插件已经提供的操作、治理和恢复能力。表中的“保留”表示能力仍需存在，不表示沿用旧实现。

## 1. 为什么需要单独的功能对等层

架构契约解决“各模块如何协作”，功能对等层解决“用户原来能做什么，新体系是否仍然能做”。两者不能互相替代：

- 只完成公共 DTO，可能丢失导入、修正、搜索、页面治理、重试和恢复等成熟能力；
- 只逐项搬运旧功能，可能把旧的词表、固定阈值和旁路依赖一起搬进新框架；
- 暂缓的领域仍要登记能力状态，不能因为暂不接入主链就让功能从设计中消失。

重建前为每项能力建立 `CapabilityCoverage` 记录：

```text
capability_id
domain
owner_plugin
user_visible_behavior
old_entrypoints[]
new_contract_refs[]
state                 retained | redesigned | deferred | removed
replacement_or_reason
scope_and_permission
failure_and_recovery
verification_cases[]
```

`removed` 只能表示经过评审后有意删除，并写明替代路径或用户可见变化；没有记录的能力视为遗漏，不能以“新框架尚未实现”带过。

## 2. 功能覆盖矩阵

### 2.1 陪伴核心、扮演与主动

| 能力簇 | 必须保留或重新设计的用户能力 | 新框架约束 |
| --- | --- | --- |
| 对话主链 | 私聊、群聊、跨平台会话；流式/分段回复；工具调用；历史写入；多 Bot/多人格切换 | 统一 `ConversationPipeline`，明确 history/delivery owner；群聊成员和私聊内容隔离 |
| 扮演表达 | 人格设定、关系距离、称呼、语气、场景连续性、自我生活、表达姿态、文本/语音/媒体表达 | AI 负责语义和表达选择；代码只校验事实、权限、附件和回执，不能靠词表改写人格 |
| 角色连续性 | 未完成事项、承诺、正在进行的活动、物品/衣物/地点/计划变化、跨会话恢复 | 使用 `PersonaContinuityState` 和带证据的事件；过期或冲突状态不能继续作为当前事实 |
| 情绪与关系 | 情绪事件、目标归因、强度/持续性/可靠性、关系变化、情绪余波、用户纠正 | `AffectEvent` 与 `MemoryAtom` 分离；Bot 自己生成的情绪句子不能反向制造事实 |
| 主动陪伴 | 事件触发、时间触发、未完成事项、关心/分享/提醒/邀请等候选；主动或沉默；被新消息吸收、取消、延后 | `signal → motive → candidate → policy → delivery`；理由文本不能反向驱动动作 |
| 主动治理 | 免打扰、临时边界、持久 opt-out、冷却、每日预算、未回应减速、占用态、撤回和反馈 | 边界解析为带 scope/TTL 的结构化对象；普通风格词不能成为硬拦截条件 |
| 管理与可解释性 | 查看候选、拒绝/延后原因、当前能力状态、审计和诊断 | 展示结构化状态和证据，不展示思维链；每次静默、降级和失败都有原因 |

### 2.2 记忆

| 能力簇 | 必须保留或重新设计的用户能力 | 新框架约束 |
| --- | --- | --- |
| 采集与分层 | 对话事件、稳定事实、偏好、承诺、关系、Bot 自我资料、临时会话记忆、摘要 | AI 提交 `MemoryProposal`；Runtime 校验证据、归属、保留期和冲突 |
| 召回与注入 | 语义召回、时间/当前性、开放事项、关系/情绪/自我连续性、摘要+最近尾部、按用途预算 | 召回候选与答案证据分层；不能让无关 Bot 事件挤占用户问题所需证据 |
| 记忆治理 | 查看、编辑、置顶、删除、撤回、纠正、过期、冲突历史、按作用域限制 | 修正传播到索引、摘要、注入和缓存；旧缓存不能恢复已失效事实 |
| 后台维护 | 待处理队列、摘要边界、嵌入生成、衰减、重试、死信、重启续跑 | 使用游标、租约、generation 和幂等键；失败保留原始证据，不静默丢失 |
| 数据迁移 | 导入、导出、旧格式兼容、按用户/人格/会话迁移、备份恢复 | 单一权威写入；迁移可暂停、校验、回滚或按作用域删除 |
| 评估与反馈 | 召回命中、答案完整性、误归因、无权候选、用户反馈、基准回放 | 指标同时记录候选级、证据级和最终注入级结果 |

### 2.3 现实触及与实时共处

| 能力簇 | 必须保留或重新设计的用户能力 | 新框架约束 |
| --- | --- | --- |
| 现实观察 | 摄像头/音频/位置/健康/天气/设备状态、手动刷新、最近观测和新鲜度 | 原始数据留在提供方；Kernel 只接收带 ACL、TTL、脱敏和证据引用的 `Observation` |
| 现实动作 | 提醒、设备控制、移动端动作、取消/撤销、动作结果查询 | capability + consent + 风险级别 + `ActionReceipt`；离线和未知状态不可伪造成成功 |
| 共处房间 | 建立/邀请/加入/离开、参与者权限、人格快照、临时上下文、文本/语音/媒体 | `SessionRecord` 统一生命周期；票据、参与者和媒体范围按会话隔离 |
| 长活动 | 共同观影、共读、通话、暂停/恢复、进度同步、断线重连、结束摘要 | 实时帧不进入普通主动额度；旧代会话不能写回新实例 |
| 经历沉淀 | 活动中的事件、结束后的摘要、可选长期记忆、用户拒绝保存 | 先生成 `MemoryProposal`，不能把所有活动原文自动长期保存 |

| 创作 | 项目/章节/版本、续写、审校、创作记忆、封面关联、发布授权 | 第二优先级；QQ 空间发布暂缓但不删除作品能力 |
| 直播 | 直播 Session、弹幕、字幕、TTS、VTS/OBS、重连、低延迟输出、投递回执 | 第二优先级；逐帧事件不触发普通主动链 |
| 屏幕 | 采集授权、脱敏、采样、活动摘要、原始媒体留存、断流、日记 | 第二优先级；旧画面过期后不得作为当前事实 |
| 游戏 | 房间、玩家、席位、邀请、对局事件、引擎生命周期、结束摘要 | 第二优先级；先冻结 Session 和资源边界 |
| 问题治理 | 诊断引用、事件回放、人工审批、修复提案、审计闭环 | 暂缓外围，不进入普通陪伴主链 |

## 3. 迁移时的能力状态规则

每个 `CapabilityCoverage` 必须有一名 owner、一个新契约引用和至少一个验收场景。迁移顺序遵守以下规则：

1. `retained`：新入口已经覆盖旧用户可见行为，并通过作用域、失败和恢复验证；
2. `redesigned`：行为目的保留，但内部机制改为 AI 语义 + Runtime 不变量，必须记录前后差异和兼容策略；
3. `deferred`：暂不接入当前主链，但要保留能力描述、缺失状态和未来接入契约；
4. `removed`：只有在有替代方案、迁移说明和用户可见影响记录后才能使用。

以下情况不能宣称功能对等：

- 只有“能调用”而没有发送、持久化、重试、取消或恢复结果；
- 只有记忆 ID 命中，答案所需的完整证据没有进入上下文；
- 只有主动候选生成，没有占用态、预算、冷却、反馈和未知投递处理；
- 只有房间创建，没有参与者权限、断线恢复和结束收束；
- 只有设备观测，没有新鲜度、授权撤销和离线语义；
- 只有页面入口，没有对应的领域 API、审计和错误状态。

## 4. 防硬编码要求

功能对等不等于复制旧实现。旧词表和规则审计中的每条记录先归类为 `sense`、`detector`、`constraint`、`transition`、`protocol`、`redaction` 或 `legacy_cleanup`，再决定是否进入新契约：

- 语义判断交给 `IntentGraph`、`AffectEvent`、`MotivePlan`、`MemoryProposal` 等结构化 AI 产物；
- 代码只校验结构、权限、作用域、证据、预算、协议、幂等和生命周期；
- 同一文本在用户输入、引用、模型输出、外部标题、内部备注和日志中的处理由来源字段决定，不能做全局子串拦截；
- 固定阈值只用于资源和安全不变量，不能用来规定角色必须如何表达或何时必须主动；
- 设计验收必须包含同义表达、否定、引用、转折、反话、多意图和无关键词表达。

## 5. 功能对等验收包

每个领域迁移至少提交：

1. `CapabilityCoverage` 清单及旧入口映射；
2. 成功、缺失依赖、权限拒绝、超时、未知、取消、重载和恢复案例；
3. 用户可见行为前后对照，标注保留、重新设计、暂缓或删除；
4. 作用域、证据、缓存和审计检查结果；
5. 旧硬编码反例回放结果，以及未枚举新语义的通过结果。

只有当清单中没有未说明的能力，且 P0 契约与对应失败路径通过后，才能关闭旧兼容入口。
