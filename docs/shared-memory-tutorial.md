# 共享记忆配置教程

这篇教程解决一个常见误会：**“另一个窗口说过的话，这个窗口为什么不知道？”**

先记住一句话：

> 陪伴插件共享的是「同一个角色 + 同一个私聊对象」的长期记忆，不是所有窗口的聊天记录。

不同 Bot、不同角色、不同用户之间默认是隔离的；多 Bot/多平台窗口需要先做「用户窗口合并」。

---

## 一、先判断你属于哪一种“不共享”

| 场景 | 默认行为 | 要做什么 |
| --- | --- | --- |
| 同一个 Bot、同一个角色、同一个用户，两个私聊窗口 | 长期记忆按角色 + 用户共享 | 一般不用配置；检查记忆是否启用、是否已经完成记忆提取 |
| 两个不同 Bot 账号，但同一个人 | 默认按 Bot 隔离 | 在「账号与会话」把窗口合并到主窗口 |
| 同一个 Bot，但两个不同角色/人格 | 默认按角色隔离 | 把两个窗口映射到同一个 AstrBot 人格/角色 |
| 两个不同用户 | 永不共享 | 这是隐私边界，不能合并 |
| 刚说完一句话，另一个窗口立刻要“知道” | 长期记忆不是聊天记录，提取有延迟 | 用「跨窗口在场」承接短时话题，或等记忆提取完成 |

### 三个概念不要混

1. **长期记忆**：事实、偏好、关系、共同经历。按角色 + 私聊对象存储，可以跨窗口召回。
2. **跨窗口在场**：最近一小段时间的片段提示，默认约 30 分钟、最多几条，只用于自然接话，不是完整记忆。
3. **聊天记录**：插件不会把另一个窗口的原文整段塞给当前窗口；群聊和私聊之间还有更严格的可见性边界。

---

## 二、同一 Bot 下的两个私聊窗口

如果两个窗口是同一个 Bot、同一个角色、同一个用户，长期记忆本来就应该共享。检查：

1. 「陪伴小屋 → 记忆与反思」里记忆功能已启用。
2. 两个窗口在「账号与会话」里映射到**同一个角色**，不是同一个人格的两个不同角色 ID。
3. 记忆不是即时聊天记录：刚说完的事实可能需要等本轮记忆提取/反思完成，另一个窗口才会召回。
4. 用 `陪伴 记忆 <线索>` 或 `陪伴 长期记忆 <线索>` 在当前窗口验证，不要只看普通闲聊。

如果仍然不共享，记录两个窗口的 Bot、角色、用户，以及发生时间，再看下一节的窗口合并。

---

## 三、不同 Bot / 不同平台的窗口：用户窗口合并

适用于同一个用户在不同 Bot 或不同平台下的两个私聊窗口。

1. 打开「陪伴小屋 → 账号与会话」。
2. 在「用户窗口合并」里，先选中要作为主窗口的当前窗口。
3. 在「要合并的窗口」里勾选另一个私聊窗口。
4. 「合并方式」选择：
   - **只共享角色（保留各自窗口）**：角色和长期记忆共享，回复仍回到各自窗口。大多数情况选这个。
   - **主窗口接管（回复统一到当前窗口）**：角色、记忆、回复和主动联系都归主窗口。只想在一个窗口聊天时选这个。
5. 保存后重载插件或重启后端，让宿主重新绑定窗口。
6. 在两个窗口分别确认：`陪伴 状态` 里的角色一致，`陪伴 记忆 <线索>` 能查到同一条资料。

> 合并的是**同一个用户**的窗口。不要把两个不同用户的私聊合并，否则会破坏隐私边界。

---

## 四、使用「我会牢牢记住你」等外部记忆插件

陪伴插件支持外部记忆 Provider，但“装了就自动全量共享”并不成立，取决于对方插件是否实现了跨窗口读取。

- 如果外部插件注册的是 **补充读取**：陪伴插件仍保留内置记忆，外部资料作为补充注入；两边都应按角色 + 用户过滤。
- 如果外部插件声明 **`handles_model_memory=True`**：模型侧记忆交给它，陪伴插件会让位；这时跨窗口是否共享由该插件自己的作用域决定，陪伴插件不能替它扩大范围。
- 只安装插件、没有注册活动 Provider，或者 Provider 被停用，陪伴插件会回到自己的内置记忆。

建议在外部记忆插件里确认：

1. 记忆/共享功能已开启；
2. 两个窗口的身份被识别为同一个用户 + 同一个角色；
3. 没有把“会话 ID/窗口 ID”当成记忆主键；
4. Provider 在「陪伴小屋」的记忆状态里显示为活动。

如果外部插件按窗口隔离，正确做法是改它的共享范围，而不是在陪伴插件里反复开关“跨窗口在场”。

---

## 五、跨窗口在场怎么用

「陪伴小屋 → 配置 → 熟人卡」里有：

- **启用跨窗口在场**：记录并注入最近的相关片段。
- **承接回看分钟**：默认 30 分钟。
- **最多几条群摘要**：默认 3–4 条。

它适合这种场景：

- 用户在群里说“我去吃饭了”，马上私聊继续这个话题；
- 角色刚从另一个窗口过来，需要一句自然的承接。

它不适合：

- 期待另一个窗口记住几个月前的完整对话；
- 期待跨不同用户共享私密内容。

长期事实请使用记忆功能，短时衔接才用跨窗口在场。

---

## 六、保存角色映射时提示“插件配置无效”

这句话通常不是角色映射本身的问题，而是保存前会顺带校验整个宿主配置；其中常见的拒绝来源是旧版的 `segmentation`（回复分段）或 `voice_reply`（语音回复）字段：

- 如果提示里出现 `segmentation`：旧版分段字段或自定义正则不兼容；
- 如果提示里出现 `voice_reply`：旧版语音触发/模式字段不兼容；
- 如果提示里出现 `profile directory`：`multi_host.installation_id` 或数据目录无法解析；
- 如果提示里出现模型相关字段：先在 AstrBot 模型配置里启用一个可用的文本 Provider。

新版会在**插件启动时和保存角色映射时**自动修复这两类旧字段：保留合法字段，只移除导致校验失败的那一项；启动日志会记录修复项，保存时页面也会提示「已自动修复旧配置（segmentation: ...）」。模型 Provider、数据目录这类问题仍需要手动处理。

如果修复后还是失败，页面会把后端的具体原因带出来；看到具体字段后，到 AstrBot 插件配置里修正该分区（或恢复默认值），再回到「账号与会话」重新保存角色映射。保存失败时页面显示「尚未保存」是正常的，说明旧配置没有被覆盖。

## 七、一分钟自检

按顺序检查：

1. 两个窗口是同一个用户吗？
2. 是同一个 Bot 吗？不是的话，做「用户窗口合并」。
3. 是同一个角色/人格吗？不是的话，统一角色映射。
4. 记忆功能启用了吗？
5. 刚说完的内容是否已经完成记忆提取？
6. 是否安装了外部记忆插件？它是否活动、是否按窗口隔离？
7. 合并后是否重载/重启过？

满足以上条件仍然不共享，再带这些信息反馈：

- 两个窗口各自的 Bot、角色、用户；
- 是否使用外部记忆插件及插件名；
- 发生时间；
- 「陪伴 记忆 <线索>」的结果；
- 脱敏后的控制台日志。
