# V2 开发者日志

2026-10-10 起普通私聊与获准群聊由 AstrBot 核心生成和发送。插件日志中的「核心回复准入检查」「交由 AstrBot 核心回复管线」「核心回复阶段结束」对应 V2 接入点；模型和工具细节查 AstrBot 核心日志。小屋治理页按本轮真实核心请求、工具阶段和发送返回提供统计，未观测字段保持未知；`send_returned` 不代表客户端送达。Token、耗时与缓存观察只保存结构元数据，不保存完整请求或回复。

普通核心聊天在唤醒主模型前执行已启用的 Laya 分类。INFO 日志中的 `Laya 核心接话判断` 包含 `event_ref`、`turn_id`、`status`、实际启用的 `action`、跳过/失败原因、失败原因的真实说明和 `elapsed_ms`；`reason_detail` 只在配置被拒绝等可操作失败时给出具体字段与合法取值，没有说明时记 `-`。等待或沉默另有 `Laya 决策跳过主模型`。`非@群核心回复候选` 只是规则筛选，最终群日志的 `reason_source=laya/model/policy` 区分分类模型、主模型选择与规则来源。Laya 关闭、分类全部关闭、引用机器人消息和调用失败都会留下明确状态；调用失败继续原有处理。复读是否参与也先经过已启用的 Laya，放行后沿用固定复读动作，不调用主模型生成复读正文。

私聊在 Laya 判定之外另有确定性的收尾判断：INFO 日志 `私聊收尾判断` 记录 `event_ref`、`turn_id`、`status`、`action`、`reason`、`last_reply_at`、`categories` 和 `elapsed_ms`，不记录消息正文；实际跳过默认模型时另记 `私聊收尾判断跳过主模型`。该判断只使用已授权的原生对话和 `conversation.presentation` 中的三个收尾配置，读取失败时继续普通回复；它不是 Laya 调用，不写入 `laya_decision_events`。跳过后的核心观察沿用 `generation_state=suppressed`，请求和发送计数为零。

撤回通知受理后记 `已记录消息撤回`（含 `notice`、scope、message_id 与 withdrawn_inputs/revoked_quotes/recalled_replies），重复通知按同一消息与路由幂等。群管理员撤回他人消息时，标记仍按消息与路由命中原文作者；核心回复在发送前再次检查触发消息，已撤回则拒绝发送。`msg_id` 作为 `message_id` 的兼容别名读取。核心管理员在聊天中明确询问撤回内容时，本轮上下文注入最近 5 条有界摘要；普通提及「撤回」不触发，非核心管理员只得到权限说明，不注入原文。

纯文本私聊在进入核心回复前还有自适应防抖。每次被动防抖用 INFO 记录一行：`收到唤醒消息`（含 `channel`、`reason`、target、完整唤醒正文和静默窗口），`防抖期间收到后续消息`（含后续正文、序号和已等待时间），以及 `防抖结束`（含输入条数、后续条数、实际等待时间和「未接收到后续/收到 N 条后续消息」）。普通群聊核心回复另有同群同成员纯文本短窗口；合并时只记 `群聊连续输入合并` 的 target 和条数，不在未准入消息上记录正文。V2 独立批次仍使用 `防抖时间` 和 `防抖结束`。私聊合并事件在入站台账中的原因代码为 `private_debounce_merged`，属于 deliberate silence。图片、引用、媒体和命令不进入文本合并；私聊静默窗口与 `prepare_core_reply` 并行，群聊短窗口先于候选判断。私聊日志正文超过 8000 字会截断并标注剩余字符数。

Laya 配置全局生效，所有私聊、群聊和人格读取 `decision/settings.json`。升级时采用最近保存的旧 Laya 配置，保留旧文件；从任意目标的模型页保存都更新同一份配置。模型页近期记录仍只展示当前授权会话，通过同一 `turn_id` 与效率记录关联实际调用、跳过、失败及耗时；私聊等待/沉默也有样本，主模型请求和发送计数保持为零。群判断使用当前已授权窗口的最近发言，群规则筛出的问题、图片与复读不构成强制回复。

本地与远程调用显式指定 `multilingual`，避免 Laya 自动语言路由因 JSON 英文字段选择其他模型。本地优先直接加载已完整下载的多语言权重；没有缓存时保留官方首次下载流程。调用超时适用于本地推理和远程连接，失败记录原因并继续原有核心流程。

启用已缓存的本地模型时，在插件加载或模型页保存后异步预热。`Laya 本地模型就绪` 单独记录设备与 `initialization_ms`，不把依赖导入和权重加载混入回复推理耗时。预热期间的消息记录为 `skipped/laya_initializing` 并立即沿用普通流程，不反复等待完整调用超时，也不排队执行已经过期的消息判断。

本地检查点目录 `local_model_path` 也属于全局配置，模型页可选择已下载的微调模型；留空使用官方多语言模型。选择的目录不完整时明确记录 `laya_model_path_invalid`，不会悄悄改用其他权重。发行包仍不包含任何模型本体或本机检查点路径。

Laya 的 `[开发者追踪]` 输入、分类问题、原始答案和合同转换适用于核心聊天和历史回复链。以下合同/正文/分段阶段属于 V2 独立模型任务和历史回复链，普通核心聊天不再执行这些步骤。

连续接话置信阈值只约束 `active_follow_up` / `reply_follow_up` 两个非点名续接候选：读取 Laya 行动答案的 `answer_confidence`，严格 SystemOne 响应缺少该字段时回退到 `probabilities[choice]`，低于设置百分比就把生效行动改为 `silent`，INFO 行同时给出原因 `laya_followup_confidence_below_threshold`。明确 @、直呼、引用及其他插话路径不受此阈值限制；远程服务没有返回概率时保持原行动，并在处理记录中标记 `confidence_unavailable`。

Laya 输入同时记录结构化 `state` 和实际送入分类器的 `model_state`。后者以当前发言开头，用简明语句呈现宿主确认的群聊、@、媒体事实和已授权历史；不把账号、人格绑定 ID 或规则触发原因当成语义要求。分类器只返回类别，不产生等待时间或段数。

模型页的「Laya 调用日志」会保留实际发送的 `state` 与分类问题、原始模型响应、合同解析结果、私聊范围修正，以及核心回复准入最终采用的分类和是否跳过主模型；失败调用显示已构造的输入、是否发出请求以及可用的响应阶段，规则跳过不会伪装成模型调用。每个授权目标最多保留最近 2000 条，旧记录仍显示原有状态与耗时，但没有新增诊断字段。

需要还原一次模型调用时，在 AstrBot Dashboard 打开「插件 → astrbot_plugin_private_companion_v2」，把「日志级别」改为 `DEBUG`。插件日志级别是动态读取的，通常不需要重载插件；恢复为 `INFO` 后就不再输出完整提示词和正文。

在插件日志面板或 AstrBot backend 日志中搜索 `[CompanionV2][开发者追踪]`。独立 V2 生成任务按需要留下以下记录：

- `模型提示词组装`：V2 组装的 system、user、工具目录和输出协议。
- `实际模型请求`：经过 AstrBot provider 准备后实际发送的 payload。
- `模型原始回复`、`原生解析输入`、`原生解析结果`：Provider 返回值和宿主解析结果。
- `模型正文处理 stage=decoded`：合同解析后的正文、claims 和工具调用。
- `正文处理`：表达复核、现实承诺保护、规范化、语音标签移除、分段、清理后的最终正文。
- `回复正文已通过校验`：最终写入发送批次的可见分段。

角色状态维护使用同一前缀，并额外记录 `状态维护提示词`、`状态维护模型正文` 和 `状态维护正文解析`。维护失败时，`后台任务异常`、`模型网关任务错误` 或 `状态维护处理失败` 记录会附带 Python traceback，可沿 `task=` 和 `round=` 对齐同一次执行。

日志会保留文本正文和 JSON，但图片、音频、视频的长 `url`、`data`、`data_base64` 等内容会替换为长度占位符，常见密钥字段会替换为 `<secret omitted>`，避免把二进制或凭据写入日志。日志包含用户内容和角色提示词，只在排查问题时临时启用 DEBUG。
