# 主动消息测试：收件人、关联转发与额度豁免

## 多核心管理员收件人

消息类型卡片不再复用首次绑定向导的唯一管理员目标。只有一个可用核心管理员时自动使用；存在多个可用目标时，在测试顶部选择并保存。首次绑定向导的既有流程不变。

保存的是服务端核验过的完整私聊目标身份，位置为运行数据根的 `setup/diagnostic-recipient.json`。运行测试前后及来源生产后重新核对当前管理员权限、目标和角色；撤权、目标被移除或身份变化时明确拒绝，不沿用失效选择。保存期间和测试运行期间互斥，未保存的选择不能启动测试。

## 允许转发到关联账号

测试顶部使用现有页面开关样式提供「允许转发到关联账号」，默认关闭，只影响本次请求，不修改生产渠道策略。

- 关闭：只发送到已选择或唯一可用的核心管理员账号。
- 开启：以所选账号为策略起点，按现有关联策略选择渠道，支持指定、加权随机及明确未发送后的安全回退，不向所有关联账号广播。

允许关联转发需为明确的布尔值，且仅供管理员测试使用。标记进入任务去重摘要和已保存的联系记录，不能靠重放同一任务改变路由。结果分别显示策略起点与实际投递目标。

## 测试额度豁免

管理员主动测试不受每日联系额度限制，包括关联候选筛选和发送前复核。豁免以服务端已持久化的 `administrator_test: true` 为准，不信任客户端直接声明。转发到其他关联账号的测试也不占用目标账号的生产联系额度。

不修改全局、窗口或关联组的额度值，不改变生产联系的额度规则。候选账号仍检查身份、权限、角色、主动联系和目的开关、暂停、免打扰、随机权重及平台连接。测试豁免不能强行启用对方账号或绕过授权。

## 路由拒绝与回执

每个候选账号的拒绝码保存在独立的 `account-link-rejections:<delivery_id>` 元数据中，重启后仍可读取。它是诊断记录，不是发送凭证，也不会占用真实发送日志的位置。

后台日志记录拒绝码；消息测试沿用已有诊断步骤，展示账号、具体原因和错误码，例如额度不足、暂停、免打扰、权重为 0 或连接不可用。未匹配中文说明的拒绝仍保留原错误码，不回显原始异常或聊天内容。

发送前终止时，投递与回执步骤标为失败，不再一直显示待检查；不使用生成任务的成功标记 `owner_result` 充当投递失败原因。未知结果和已接收但未确认的投递仍禁止跨账号重发。

## 验证入口

- `tests.test_astrbot_setup_api`：多管理员保存、唯一管理员默认、撤权后失效、关联转发参数及路由失败展示。
- `tests.test_account_link_delivery`：真实任务和 outbox 配合合成回执，覆盖共享额度为 0 时测试可发送、生产额度仍受限、测试不占目标额度、其他限制保留、逐账号拒绝持久化，以及未知结果不回退。
- `tests/test_contact_page.cjs`：选择保存、运行锁、关联转发确认和诊断显示，复用已有页面样式。

测试使用隔离数据根及合成账号，不连接生产数据库或真实机器人。修改页面后运行 `tools/sync_framework_page.py` 及 `--check`。
