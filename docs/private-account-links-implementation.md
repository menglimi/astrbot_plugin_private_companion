# 同一人格私聊账号关联

## 范围与入口

在「关系与权限」的私聊成员详情中打开「关联用户」，选择映射到同一角色、同一原生人格的具体私聊账号。每组可关联 2–16 个账号，同一人格下的账号不能重复加入其他组。群聊、通配目标、人格映射不明确的账号，以及仍使用旧主窗口接管的账号不能加入。

账号关联不会自动打开共享。上下文、资料、回复设置、联系偏好和身份权限分别设置；主动联系渠道也需单独选择。页面使用已有成员编辑器的按钮、表单、开关和主题样式。

## 上下文与往来记录

- 开启上下文共享后，仅从开启时间起的新对话投影跨账号背景，不搬迁或改写旧记录。增加成员或重新开启共享时重置共享起点。
- 每次读取会复核来源账号、角色、对话权限、来源撤销和消息撤回状态。助手消息只有实际发送确认后才进入背景，排队期间晚于当前输入才发出的回复不注入本轮。
- 跨账号内容只作为背景，不替换当前会话身份、受众、scope 或被动回复地址。关闭共享或解除关联后，后续请求停止注入。
- 往来记录可按关联组汇总展示，每条记录保留原账号和原始归属。

## 设置与权限

人工关系资料、回复设置和联系偏好可按类别或字段共享。首次开启时明确选择初始来源；共享期间各账号编辑同一份有效值，关闭共享后恢复各账号未被覆盖的原值。

共享设置接入现有 ConfigurationService、配置 owner 和成员编辑入口。关联组与共享值保存在配置侧库的既有 `runtime_metadata` 中，使用版本校验和稳定操作键处理并发及重复提交，不新增数据库表。

身份权限使用独立开关和确认，不改写各账号原有 grant。关联路由仍检查账号本地的主动联系禁用、暂停和免打扰限制；共享开关不能代替这些检查。

## 主动联系渠道与权重

渠道策略为关闭、指定账号或随机可用账号。随机策略为每个成员保存 0–1000 的整数权重，默认 1，至少有一个正权重。权重 0 不参与新联系的随机选择及确认未发送后的回退；旧策略没有权重字段时保持等概率。

先检查身份权限、角色、联系偏好、额度和连接可用性，再对可用账号按权重无放回抽取。页面占比只表示全部账号可用时的参考概率。

投递继续使用原有主动任务和 outbox，不另建发送通道。只有平台明确返回未发送，才可回退其他账号；已接收、未知结果、异常或超时都不能据此跨账号重发。多段消息一旦进入已接收或未知状态，后续段落锁定同一账号，即使该账号权重随后改为 0。所有账号不可用时交回原任务的有界重试。

## 接口与嵌入页面

Dashboard 接口包括读取关联、读取汇总历史、保存关联和解除关联。服务端从当前配置解析账号、身份和角色，不接受客户端伪造上下文。保存失败或超时时保留草稿和原操作键，供读回或安全重试。

小屋外层桥只精确放行这些关联接口，不扩展其他工作区、任意路径前缀或方法。修改页面后运行 `tools/sync_framework_page.py`，同步嵌入工作区、bundle 和页面清单。

## 限制

- 上下文共享接入原生核心回复背景，不承诺其他扩展的独立对话入口自动共享。
- 每次最多读取 96 条候选，投影最多 24 条、10000 字符；不是无限历史共享。
- 输入异步落库，几乎同时到达的跨端消息可能暂时互不可见，没有跨平台生成串行锁。
- 已发送给模型或出现在回复中的内容不能通过关闭开关撤回。
- 不改变已有长期记忆及其他跨窗口感知功能的独立开关。
