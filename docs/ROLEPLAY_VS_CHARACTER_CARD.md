# 从角色卡到角色在场

## ——传统单纯角色卡与陪伴插件的八模块对比

先把“传统单纯角色卡”说清楚，避免把它写成稻草人。

它通常是一段静态文本：名字、年龄、性格、背景、说话风格，可能再加几句示例对话。使用时把它塞进系统提示词，模型每轮根据这段设定和聊天记录生成回复。它便宜、直接、可复制，一张卡可以带到任何支持自定义人格的客户端里。

对一次性短对话，这已经够好。

但如果目标是“长期陪伴”，角色卡会碰到一个结构性上限：**它定义的是“她是谁”，没有定义“她如何一直是”。**

下面按八个模块对比。

| 模块 | 传统单纯角色卡 | 这套插件 | 本质差异 |
| --- | --- | --- | --- |
| 一、定位 | 一张会说话的设定 | 一个有连续性的角色运行时 | 静态快照 vs 持续在场 |
| 二、角色底座 | 一段人格文本，手工改 | 宿主人格 + 角色档案 + 三层配置 + 版本 | 单文件 vs 分层、可追溯 |
| 三、对话内核 | 每条消息都进模型 | 先准入、防抖、判沉默，再组装上下文 | 全都回 vs 先决定该不该回 |
| 四、拟人表达 | 靠提示词要求“像她” | 确定性分段、去重、引文保护、多模态 | 口头约束 vs 管线保证 |
| 五、关系与记忆 | 一个角色对所有人，记忆靠上下文窗口 | 身份绑定、关系网、来源记忆、跨窗口 | 单会话 vs 多用户连续 |
| 六、生活与主动 | 静态设定，最多加定时器 | 状态、日程、感知与候选生命周期 | 到点输出 vs 有理由开口 |
| 七、群聊人格 | 把群聊记录丢给模型 | 发言者归因、参与判断、该沉默时沉默 | 回复机器 vs 社交参与者 |
| 八、成长与边界 | 直接改提示词，改完即生效 | 人格版本、表达审核、权限与投递回执 | 手工信任 vs 可治理运行时 |

---

## 一、定位：角色卡是设定，插件是运行时

**传统卡**：角色卡是一份“设定文档”。模型每次生成前读一遍，然后即兴发挥。它不关心上一轮和这一轮是不是同一个人，也不关心换一个窗口还记不记得。

**问题**：单轮可以很像，多轮容易漂。用户换群、换私聊、隔一天再来，角色可能重新自我介绍，或者把别人的称呼安到当前用户头上。

**这套实现**：把角色拆成“身份、关系、生活、表达、边界”五个连续面。普通回复继续交给 AstrBot 核心管线，插件补宿主不负责的部分：入站准入、关系与记忆、生活状态、主动候选、投递审计。

**实现落点**：`core_reply`、`relationships`、`role_work`、`proactive`、`delivery`。

**对比结果**：角色卡回答“她是谁”；运行时回答“她为什么现在说这句话、凭什么记得、什么时候不该说”。

---

## 二、角色底座：一段文本 vs 分层人格

**传统卡**：所有设定写在一段文本里。想改性格就改这段，想换口吻也改这段。改完没有对照，也没有回退，只能凭感觉判断“是不是更好了”。

**问题**：人格越改越厚，前后设定互相冲突；不同窗口需要不同语气时，只能复制多张卡；角色卡一多，哪张才是“本人”说不清。

**这套实现**：

- **AstrBot 人格**是普通对话的主人格，插件不重复注入“自我”，避免同一段人格在上下文里出现两次；
- **角色自我档案**给后台任务使用，档案为空时回退到 AstrBot 人格，不凭空造新人；
- **三层配置继承**：安装与连接设置 → 角色默认设置 → 用户/群聊窗口设置，具体窗口优先，但不反向改写角色底座；
- **人格工坊**保留宿主原人格，在旁边做草稿和版本：支持基于原人格优化或从零共创，按定位、性格、口吻、背景、复核五阶段推进，可对话修改、生成草稿、试演口吻；每次保存都是新版本，撤回也留记录，每版都保留“当时对照的原人格”。

**实现落点**：`persona_craft`、`persona_designer`、`role_profile`、`system_prompts`。

**对比结果**：角色卡是“一份设定”；插件是“一份可继承、可对照、可回退的人格资产”。

---

## 三、对话内核：每条都回 vs 先判断该不该回

**传统卡**：用户发一条，拼上人格和最近几条聊天记录，调用模型，返回。群聊里通常也是每条都看、每条都可能回。

**问题**：用户连发三条碎消息，会被拆成三次回答；一句“晚安”可能触发“晚安—晚安”的死循环；群聊里每条都接，很快变成复读机。Token 花了不少，拟人感反而下降。

**这套实现**：

1. **入站准入**：先看私聊权限、群参与资格、当前是否忙碌/收尾；
2. **连续输入防抖**：第一条纯文本不立刻调模型，开 1.5–8 秒自适应窗口，后续文本合并成同一轮，用户停手才回复；
3. **确定性沉默**：收尾后的晚安、道别、感谢、短应声跳过模型调用并记入沉默台账；带问题、请求、图片或新话题仍正常回复；
4. **提示词分层**：固定层放拟人策略、身份锚点、表达规则，动态层放当前时间、状态、日程、环境、跨窗口连续性、群参与提示，合并成仅本轮有效的用户内容块，不写回宿主历史。

**实现落点**：`private_debounce`、`core_reply`、`system_prompts`、`conversation/foreground`。

**对比结果**：角色卡把“回不回”交给模型即兴判断；插件把“回不回”变成前置的确定性决策，模型只负责“怎么回”。

## 四、拟人表达：提示词要求 vs 管线保证

**传统卡**：在人格里写“说话要自然、简短、有口癖、不要像客服”。效果完全取决于模型这一轮听不听话。

**问题**：模型可能复读、留内部标签、把引文拆坏、一段话拆成七八条；加表情包、语音、贴图时，文本和媒体经常不同步。

**这套实现**：

- **智能分段**：按句子和语义断句，开引号、开括号不作为断句点，受保护的引文内部不强拆；
- **去重与清理**：合并完全相同的整段复读，清掉模型误留的内部标签，保留叠词、正常语气重复和 Markdown 代码块；
- **表达规则**：从获准对话里归纳情境短语、语法句式和避免情境，人工审核后生效，按角色隔离；
- **多模态编排**：按窗口配置决定表情包、贴图、TTS；语音按私聊/群聊和角色切换矩阵；
- **发送前自检**：检查称呼、引文、附件和平台投递能力，避免“文本发了图掉了”或“引用了不该引用的内容”。

**实现落点**：`humanized_expression`、`segmentation`、`expression`、`delivery`。

**对比结果**：角色卡把“像她”寄托在模型发挥上；插件把能确定性保证的部分从模型手里拿走，模型只负责语言本身。

---

## 五、关系与记忆：一个角色对所有人 vs 每个人有独立关系

**传统卡**：角色卡通常默认“你是我的恋人/朋友”，对每个装这张卡的人都是同一套关系。记忆就是当前上下文窗口，窗口一满就丢，换窗口就重新开始。

**问题**：

- 多用户场景下，角色对所有人用同一套称呼和亲密程度；
- 群聊和私聊的记忆混在一起，容易把 A 的话安到 B 头上；
- 上下文塞得越多，旧信息越容易淹没当前话题，Token 也越贵；
- 没有来源，角色可能把猜测写成“你以前说过”。

**这套实现**：

- **平台身份绑定**：OneBot 数字 QQ、QQ 官方 `openid`、多账号实例归到同一份关系；
- **关系网**：熟人卡、称呼、群聊关系、访问规则；陌生人走独立边界，不建身份、不写对话、不签发权限；
- **跨窗口连续性**：只匹配同一安装、同一 Bot、同一角色、同一平台、同一用户；只用对方本人在群里的公开原话和角色自己的回复；默认回看 30 分钟；不读其他群成员发言，不把私聊秘密带进群聊；
- **来源记忆**：按角色和可见性维护来源记忆、用户画像、共同经历，语义向量与关键词混合检索；每日反思从用户原话明确支持的内容里提取互动纪念日，日期取真实发生日，去重后进入感知与主动问候；
- **表达学习隔离**：只从获准对话归纳，人工审核后生效，按角色隔离。

**实现落点**：`relationships`、`identity_policy`、`memory`、`knowledge`、`expression/learning`。

**对比结果**：角色卡是“一个角色对所有人”；插件是“同一个角色，对不同的人有不同关系，但人格底座不变”。

## 六、生活与主动：到点发消息 vs 有理由开口

**传统卡**：角色没有生活。主动消息要么没有，要么外挂一个定时器：“每天 8 点发早安”。

**问题**：定时器不知道角色刚睡下、用户在忙、昨天刚聊过、今天下雨；发出来的话没有生活依据，很快变成打卡。

**这套实现**：

- **角色状态**：精力、心情、睡眠阶段、疲劳与生活余波，被中断的休息、反复叫醒、午休会留下连续影响；
- **今日日程**：以当前安排的完整标题、状态和角色原话占主位，过时段收进“已经落幕”；
- **环境感知**：时间历法、天气实况与预警、位置连续性、健康、识屏、手机状态、摄像头、智能家居等通道；
- **主动候选生命周期**：生活来源 → 形成候选 → 免打扰/起床宽限/忙碌/频率检查 → 人格复核 → 生成与投递 → 回执与未完成话头跟进。

**实现落点**：`role_work`、`agenda`、`proactive`、`scheduling`、`diagnostics`。

**对比结果**：角色卡最多能做到“按时说话”；插件追求“有理由才说话”，并且这个理由可以解释。

---

## 七、群聊人格：把记录丢给模型 vs 先看懂人群

**传统卡**：群聊里通常把最近聊天记录拼进上下文，让模型自己判断谁在叫它。

**问题**：多人上下文里，模型很容易把上一位的称呼安到当前发言者；别人提到角色名字，它可能误以为在叫自己；没人点名时也忍不住接话。

**这套实现**：

- 近期群聊原文显式携带 `speaker_id`，区分当前发言者和上下文其他群友；
- 只有本轮明确 `@` 才识别为叫本角色；`[提及账号 X]`、同名群名片、第三人称讨论角色名都不会误认；
- 同一个人在其他群的已知称呼可作为有限别名带入，但不泄露其他群号或私聊关系；
- 非点名连续接话走 Laya 行动分类校准概率，低于阈值时安静旁听，不唤醒主模型；
- 开启硬收口后，群内连续互动达到空气护栏窗口上限，未点名、非直接接续的普通消息转为旁听；明确 `@`、直呼和有依据的直接接续不受影响。

**实现落点**：`conversation/group_*`、`decision`、`participation`。

**对比结果**：角色卡在群里是“一个会回复的模型”；插件试图让角色成为“知道自己在人群里”的参与者。

---

## 八、成长与边界：改提示词 vs 可治理的运行时

**传统卡**：角色成长就是改卡。改完直接生效，没有版本、没有审核、没有回退；角色卡里写了“会永远记得你”，但没有任何机制保证。

**问题**：一次误改可能让人格漂移；表达学习没有审核会学歪；主动消息没有权限边界会越权；平台发送失败没有回执，角色可能“以为说过了”。

**这套实现**：

- **人格版本**：草稿、试演、对照、撤回都留痕，角色不会因为一次生成悄悄换人；
- **表达审核**：候选规则和样本人工通过才生效，可按角色筛选来源、拒绝重载、导出/导入含原始观察的分享包；
- **权限边界**：没有对话权限不进对话；陌生人婉拒不建身份、不写会话、不签发授权；
- **投递审计**：真实外部动作经过权限与 outbox 审计；平台结果未知时如实标记，绝不自动重放；
- **可观测**：诊断页展示真实 Token、缓存命中、TTFT、工具耗时和投递回执，宿主没提供的字段保持“未知”，不补 0、不伪装已送达。

**实现落点**：`expression/review`、`persona_craft` 版本链、`delivery` outbox、`diagnostics`、陪伴小屋治理页。

**对比结果**：角色卡靠“作者自觉”；插件把成长和边界做成可追溯、可审计的运行时规则。

## 实现方式总览

如果把这套实现压缩成一条链路，大概是：

```text
消息
  → 入站准入（权限 / 参与资格 / 忙碌与收尾）
  → 连续输入合并（私聊防抖）
  → 上下文组装（固定人格层 + 本轮动态事实）
  → AstrBot 核心回复（模型 / 历史 / 工具 / 流式）
  → 表达后处理（分段 / 去重 / 引文 / 多模态）
  → 投递与回执（平台能力 / outbox / 未知不重放）
```

后台则是另一条链路：

```text
角色状态 / 日程 / 感知 / 未完成话头
  → 主动候选
  → 免打扰 / 起床宽限 / 频率与额度
  → 人格复核
  → 生成与投递
  → 回执与跟进
```

两条链路的共同原则是：**确定性的判断放在模型前面，模型只负责语言；连续性和边界放在数据库与运行时里，不交给提示词记忆。**

角色卡仍然是这套系统的底座：它提供“她是谁”的原始文本。插件做的是在这份文本之外，补上时间、关系、生活、表达管道和治理规则。

## 什么时候角色卡更好

这不是一场“谁更高级”的比较。

**传统单纯角色卡更适合**：

- 一次性、短周期的角色扮演；
- 单用户、单窗口、不需要长期记忆；
- 想快速复制到不同客户端；
- 不需要主动消息、群聊参与和权限审计；
- 预算和运维成本敏感。

**这套插件更适合**：

- 长期陪伴，跨天、跨窗口、跨群聊；
- 多用户、多角色、多账号；
- 需要主动联系，但不想变成定时打卡；
- 群聊里需要知道谁在说话、什么时候该沉默；
- 对隐私、权限、投递回执和人格稳定有要求。

一张角色卡可以定义“她是谁”；一套运行时才能保证“她一直是”。

**最强拟人不是把角色卡写得更长，而是让角色在时间里更少破绽。**
