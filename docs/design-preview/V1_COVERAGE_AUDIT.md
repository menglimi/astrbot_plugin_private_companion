# 旧版功能与配置项对照检查

对象：

- 旧版：`_codex_backups/astrbot_plugin_private_companion_pre_refactor_20260804_115735`
- 新版原型：`docs/design-preview/index.html`
- 检查日期：2026-11-02
- 补记：检查后原型已从 29 张卡扩到 69 张；本文保留“补卡前基线”，用于对照缺口。

结论先说：

> 原型目前是“分类 + 卡片 + 详情”的导航骨架，不是旧版功能清单的完整映射。  
> 初始卡片 29 张，补卡后 69 张；旧版仅 `featureMeta` 就有 124 个功能键，仍有部分能力没有对应卡。

### 先说明：旧版只做功能对照，不做字段映射

这份检查用旧版回答的是：

- 旧版有哪些**用户功能**
- 哪些功能在新版里没有入口
- 哪些能力被合并、改名或应当删除

它**不是**说新 UI 要绑定旧版的 `enable_*` 配置键。

原因：

1. 旧版字段对应旧版代码结构；V2 有窗口、角色、安装层和任务路由，字段含义不同。
2. 旧版很多开关是重复事实源（主动权能 / 主动开关、语音 Provider / 角色语音策略）。
3. 部分旧功能按 V2 架构**不应该**迁移，强行映射会复活旧状态。
4. 真正落地时，每张卡必须绑定 **V2 现有 API / 字段**，旧字段只用于迁移对照。

正确的映射链是：

```text
旧版功能（只做覆盖检查）
  ↓
用户能力（卡片的职责）
  ↓
V2 机制 / API（事实源）
  ↓
V2 字段（详情页真正编辑的配置）
```

而不是：

```text
旧版 enable_* 字段
  ↓
直接塞进新卡片
```

## 5. 建议

原型保留现在的分类和卡片结构，但要补两层：

1. **卡片层**：补到约 50–60 张，接近旧版功能面。
2. **详情层**：每张功能卡建立 **V2 字段 / API 清单**；旧版只作为“这个能力是否存在”的对照。

在补齐之前，不建议把原型直接当成交付版本，也不建议只按现有 69 张卡接真实接口。

下一步建议：

```text
先补 P0 卡片
  ↓
给每张卡写 V2 机制 / API 映射
  ↓
旧版只做功能覆盖核对，不做字段绑定
  ↓
再接真实 V2 接口
  ↓
最后做全量配置项回归
```

这份检查保留了补卡前基线；原型已按 P0/P1 扩到 69 张卡，剩余缺口仍以本文清单为准。
