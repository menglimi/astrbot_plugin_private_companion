# 陪伴开发日记 #02｜五位数成本，七百亿 token，如何实现最强拟人

> 一篇关于成本、试错和“少犯错”的开发记录。

> 先把数字放在前面：这个项目累计烧掉五位数成本，Token 累计七百亿。
>
> 它们不是勋章，是一张很长的错误清单。

如果重来一次，我不会把预算花在“让模型更会写”上，而会花在“让它少犯错”上。

因为拟人这件事，真正的难点从来不是生成一句漂亮的话。而是：

- 这一句和上一句是不是同一个人；
- 换一个窗口，她还记不记得刚才发生过什么；
- 她知不知道现在该不该开口；
- 她会不会为了“像人”而编造一段没发生过的记忆；
- 她能不能在群聊里安静地待着，而不是每条消息都接。

这篇文章按八个模块，讲这套拟人/角色扮演实现到底把钱和 Token 花在了哪里，以及哪些地方其实可以不花。

---

## 一、定位：拟人不是文风，是连续性

很多角色插件的第一反应是写一段很长的人格提示词：她叫什么、什么性格、说话要带什么口癖。这样做能“像”，但很难“一直是”。

因为“像”只是单轮效果，连续性要同时成立四件事：

1. **身份连续**：这一轮和上一轮是同一个人，换私聊、换群、换窗口仍然是。
2. **关系连续**：她记得对面是谁、熟到什么程度、哪些话能说、哪些边界不能碰。
3. **时间连续**：她有自己的状态、日程、睡眠和天气，不是永远在线等消息。
4. **边界连续**：没有权限就不进对话，没有依据就不编记忆，没有送达就不装作成功。

这套实现的第一笔“架构成本”，是决定**不另起一套人格**。

普通私聊和群聊的回复仍然交给 AstrBot 的核心管线：模型选择、人格、会话历史、工具循环、流式输出、平台发送，继续由宿主负责。插件不重复注入一份“自我”，而是补上宿主不负责的部分：入站准入、关系与记忆、生活状态、表达节奏、主动候选、投递审计。

这个决定看起来只是“少写一段提示词”，实际上省掉了后面无数轮人格漂移、上下文重复和对照测试。

一句话概括：

> **AstrBot 负责“怎么回”，插件负责“她为什么回、凭什么记得、什么时候不该回”。**

---

## 二、角色底座：人格不是提示词，是版本

角色要稳定，首先得知道“以哪份人格为准”。

插件把角色身份分成两层：

- **AstrBot 人格**是普通对话的主人格。插件不重复注入“自我”，避免同一段人格在上下文里出现两次。
- **角色自我档案**是插件后台任务使用的稳定角色资料：日程、日记、关系反思、主动规划都从这里取角色视角。档案为空时回退到 AstrBot 人格，不凭空造一个新人。

角色之下还有三层配置继承：

1. **安装与连接设置**：Bot 账号、平台连接、存储位置和全局运行条件。
2. **角色默认设置**：这个角色自己的档案、状态、日程、语音矩阵和行为偏好。
3. **用户/群聊窗口设置**：在关系网里对具体的人或群微调回复风格、主动频率、TTS 和权限。

具体窗口始终优先于通配模板，但不会反过来改写角色底座。

人格本身也不是一段不可追溯的文本。人格工坊会保留宿主当前人格，在旁边做草稿和版本：

- 可以基于原人格优化，也可以从零共创；
- 设计过程分为定位、性格、口吻、背景、复核五个阶段；
- 支持对话式修改、生成草稿、试演口吻；
- 每次保存都是新版本，撤回也留记录，并且每版都保留“当时对照的原人格”。

这笔钱花在反复对照上：生成一版、试演、和上一版比、再改。但版本链让每次修改都有参照，角色不会在一次次调参里变成另一个人。

**人格变更有据可查，比“这一句像不像”重要得多。**

---

## 三、对话内核：最贵的不是上下文长度，是错误的时机

Token 最容易浪费的地方，不是提示词太长，而是**在不该调用模型的时候调用了模型**。

一条消息进入插件后，先过准入：

- 私聊有没有对话权限，群聊有没有参与资格；
- 是不是连续输入，要不要等用户把话说完；
- 当前是不是正在收尾、忙碌或应该保持沉默。

以私聊为例，第一条纯文本消息不会立刻触发模型。插件会开一个 1.5–8 秒的自适应窗口：用户继续发，后续文本合并成同一轮；用户停手，才进入正常回复。

现场很常见的一组消息是：

> “那就下次”
>
> “吃饱了”
>
> “好饱”

如果没有防抖，这三条会变成三次模型调用、三次回复，角色要么抢答，要么复读。合并之后，只有一轮请求，也只回一次。

真正组装提示词时，内容分成两层：

- **固定层**：拟人策略、稳定身份锚点、表达规则，放在系统提示词前部；
- **动态层**：当前时间与历法、角色状态与日程、环境感知、跨窗口连续性、群参与提示、分段与模型路由信息，合并成仅本轮有效的用户内容块。

固定内容尽量稳定，动态事实只在本轮出现，不写回 AstrBot 历史。这样既能让模型看见“此刻”，又尽量不破坏上游的 Prompt Cache。

回复之前还有一道“确定性沉默”：如果用户只是晚安、道别、感谢或短应声，而角色上一轮已经完成收尾，插件会跳过模型调用并记入沉默台账，避免双方陷入“晚安—晚安”的死循环。带问题、请求、图片或新话题的消息仍然正常回复。

**先决定该不该回，再决定怎么回。** 这是拟人的第一层，也是最省钱的一层。

---

## 四、拟人表达：多一次重生成，不如一次确定性清理

“加几个语气词”不叫拟人。真正影响像不像的，是表达里的节奏和边界。

插件在发送前会做一组确定性的表达处理：

- **智能分段**：按句子和语义断句，不把一句话拆得七零八落；开引号、开括号一律不作为断句点，受保护的引文内部不强拆。
- **去重与清理**：合并完全相同的整段复读，清掉模型误留的内部标签，同时保留叠词、正常语气重复和 Markdown 代码块。
- **表达规则**：从获准对话里归纳情境短语、语法句式和避免情境，经过人工审核后才进入表达层，并且按角色隔离。
- **多模态表达**：按窗口配置决定是否带表情包、贴图、TTS 语音；语音可以按私聊/群聊和角色切换不同矩阵。
- **发送前自检**：检查称呼、引文、附件和平台投递能力，避免“文本发出去了，图掉了”或“引用了不该引用的内容”。

这些处理不追求“每句都可爱”，而是追求**同一个人在不同场景下的表达是连贯的**：私聊可以更松弛，群聊要更短；该认真时不卖萌，该沉默时不硬接。

从成本角度看，确定性后处理通常比让模型重生成更便宜，也更稳定。模型偶尔会多留一个标签、多复读一段、把引文拆坏；这些不应该靠“再抽一次卡”解决。

**能写成代码的，不要交给提示词。**

---

## 五、关系与记忆：记忆的预算是注意力，不是 Token

角色扮演最容易破功的地方，是“换一个窗口就重新认识”。

插件用平台身份绑定把同一个人在不同会话里连起来：OneBot 数字 QQ、QQ 官方 `openid`、多账号实例都会归到同一份关系里。关系网里维护熟人卡、称呼、群聊关系和访问规则；陌生人则走独立边界：不建身份、不写对话、不签发权限，只在配置允许时回一句固定婉拒。

跨窗口连续性解决的是“刚才在群里说过，转到私聊还接得上”：

- 只匹配同一安装、同一 Bot、同一角色、同一平台和同一用户；
- 只使用对方本人在群里的公开原话和角色自己的回复；
- 绝不读取其他群成员发言，也绝不把私聊秘密带进群聊；
- 默认回看 30 分钟，让角色自然承接话头，而不是像失忆一样当第一次听。

记忆不是把全部聊天记录塞进提示词。上下文越长，角色越容易被旧信息淹没，Token 也越贵。插件按角色和可见性维护来源记忆、用户画像和共同经历，支持语义向量与关键词混合检索；每日记忆反思会从用户原话明确支持的内容里提取互动纪念日，日期取被引用消息的真实发生日，自动去重后进入感知与主动问候上下文。

**记忆的目标不是“记得多”，而是“记得有依据、取得回、说得清”。**

七百亿 Token 里，有相当一部分花在“怎么少放一点上下文，还能让她接得上”这件事上。这个钱值得花，因为它同时买到了效果和成本。

---

## 六、生活与主动：有理由地开口，也有理由地不开口

主动消息如果只是定时器，很快就会变成打扰。

插件把主动联系做成一条完整候选生命周期：

1. **生活来源**：角色状态、日程、睡眠、天气、纪念日、未完成话头、近期对话。
2. **形成候选**：不是“到点了发一句”，而是先有值得说的理由。
3. **打扰检查**：免打扰时段、起床宽限、忙碌与休息、频率和每日额度。
4. **人格复核**：候选是否符合当前角色、关系和表达方式。
5. **生成与投递**：保留图片/表情意图，检索表情包、合成 TTS，发送前自检。
6. **回执与跟进**：确认投递结果；未完成话头在用户回复后按语义判断完成、取消或更新。

角色的“生活”也不是装饰：精力、心情、睡眠阶段、疲劳和生活余波会真实影响后续状态；被中断的休息、反复叫醒和午休不是按固定时间表切换，而是留下连续影响。日程以当前安排的完整标题、状态和角色原话占主位，后续安排逐步展示，过时段自动收进“已经落幕”。

再加上时间与历法、天气实况与预警、位置连续性、健康、识屏、手机状态、摄像头、智能家居等感知通道，角色不是凭空说“今天好累”，而是有当前生活作为依据。

主动系统最贵的错误，不是“少发了一条”，而是**生成了一条不该发的消息**。所以候选要先审后生成，而不是先生成再决定要不要发。

**主动不是“多说话”，是有理由地开口，也有理由地不开口。**

---

## 七、群聊人格：群聊里最贵的不是回复，是错误地接话

群聊比私聊更容易把角色演成复读机：谁说话都接、每句都回、把别人的称呼安到当前发言者头上。

插件在群聊里先做“看懂”：

- 近期群聊原文显式携带 `speaker_id`，区分当前发言者和上下文里的其他群友；
- 只有本轮消息里的明确 `@` 才会被识别为叫本角色；`[提及账号 X]`、同名群名片、第三人称讨论角色名，都不会误认成“你在叫我”；
- 同一个人在别的群里的已知称呼可以作为有限别名带入当前群，但不会泄露其他群号或私聊关系。

然后才决定“接不接”：

- 非点名的连续接话走 Laya 行动分类校准概率，低于阈值时自动改为安静旁听，不唤醒主模型；
- 开启“硬收口”后，群内连续互动达到空气护栏窗口上限，未点名、非直接接续的普通群消息直接转为旁听；
- 明确 `@`、直呼和有依据的直接接续不受影响。

群聊里最难的不是接话，是**在该沉默的时候沉默**。角色的存在感不靠刷屏，而靠每次开口都像她。

从成本上看，群聊也是最容易失控的地方：上下文大、消息密、每条都调模型很快就烧穿预算。先做参与判断，再决定是否唤醒主模型，既省 Token，也省“出戏”的次数。

---

## 八、成长与边界：会学习，但不编造

拟人系统一旦开始“学习”，最容易越过的两条线是：把猜测写成记忆，把越权当成主动。

插件对“成长”做了两层约束：

- **表达学习有审核**：只从获准对话里归纳，生成候选规则和样本，经过人工通过才生效；可以按角色筛选来源、拒绝重载、导出/导入包含原始观察的分享包。
- **人格变更有版本**：草稿、试演、对照、撤回都留痕，角色不会因为一次生成就悄悄换人。

对“边界”则尽量做成确定性规则：

- 不伪造记忆、不伪造来源，没发生的事不写成已发生；
- 没有对话权限就不进对话；陌生人婉拒不建身份、不写会话、不签发授权；
- 真实外部动作经过权限与 outbox 审计；平台返回结果未知时如实标记，绝不自动重放；
- 私聊与群聊的隐私边界按人和窗口隔离，不把群成员发言或私聊内容互相搬运；
- 诊断页展示真实观测到的 Token、缓存命中、TTFT、工具耗时和投递回执，宿主没提供的字段保持“未知”，不补 0、不伪装已送达。

**拟人的底线是诚实**：可以不知道，可以沉默，可以说“我不确定”；但不能编一个记忆、造一个来源，或者替用户决定什么该发生。

五位数成本里，有相当一部分买的不是“更强的话术”，而是“知道哪里会坏”。

## 钱到底花在哪

下面不列具体金额，也不编百分比。一次真实请求往往同时验证人格、记忆、表达、权限和投递，无法干净拆成“人格占 30%、记忆占 20%”。

| 花费方向 | 买到的不是 | 买到的是 |
| --- | --- | --- |
| 真实链路回归 | 漂亮的测试报告 | 私聊、群聊、主动、多平台、多模态的真实失败样本 |
| 人格对照与试演 | 一句“像” | 版本差异、口吻稳定性、撤回依据 |
| 长上下文与记忆实验 | 更长的提示词 | 更少但更准的检索结果 |
| 群聊参与校准 | 更多接话 | 知道什么时候不接 |
| 主动候选验证 | 更高发送量 | 更少打扰、更可信的开口理由 |
| 故障复现 | 一次通过 | 超时、重复、越权、掉图、假成功的复现路径 |
| 表达与多模态回归 | 更多花样 | 分段、引文、表情、语音不破坏原意 |

这里的七百亿是项目累计口径，不是某个用户的一次会话；它更像一份开发期的累计账单：反复试错、回归、真实链路验证。它买到的最重要的东西，不是“最强”两个字，而是一套**知道什么时候不该说**的系统。

## 省 Token 的七个开关

如果只看成本，这套实现里最值得保留的是七个“先别调模型”的开关：

1. **先准入，后模型**：没有权限、没有参与资格，直接不进入生成。
2. **连续输入合并**：1.5–8 秒窗口，把碎消息并成一轮。
3. **确定性沉默**：收尾后的晚安、道谢、短应声不调用模型。
4. **固定前缀 + 动态单块**：保护 Prompt Cache，不把每轮事实写进历史。
5. **检索代替全量历史**：只取有依据的几条，不塞整本聊天记录。
6. **群聊先判参与**：Laya 低于阈值就旁听，不唤醒主模型。
7. **候选先审后生成**：主动消息先过打扰检查和人格复核，再生成正文。

这七个开关加起来，比换一个更大的模型更能改善“像不像”和“贵不贵”。

---

## 三个教训

### 1. Token 堆不出拟人，反而容易把角色淹死

上下文越长，角色越容易抓着旧话题不放，或者把别人的话安到当前用户头上。记忆的价值在“取得准”，不在“存得多”。

### 2. 最贵的回复，是错误的回复

多回一条、回错人、把群聊内容带进私聊、把没发生的事写成记忆——这些错误带来的信任损失，远高于省下来的那点 Token。

### 3. 能确定性解决的，不要交给模型

防抖、权限、分段、去重、回执、冷却、免打扰，这些都应该由代码保证。提示词只负责“怎么说得像她”，不负责“什么时候必须闭嘴”。

---

## 结语

七百亿 Token，五位数成本，最后买到的不是“最强拟人”四个字。

而是四个更朴素的东西：

- 她是同一个人；
- 她记得有依据；
- 她知道什么时候不开口；
- 她不为了像人而编造。

如果非要说“最强”，我更愿意把它定义成：

> **不是让模型更像人，而是让角色更少破绽。**

下一篇开发日记，我想写“为什么我们最后把一半的拟人工作，从提示词搬回了代码”。
