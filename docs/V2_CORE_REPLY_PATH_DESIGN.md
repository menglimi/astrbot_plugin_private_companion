# V2 普通回复回归 AstrBot 核心管线

2026-10-10：本文描述当前实现，替代此前“核心只生成、V2 自行发送”的设计。

普通私聊及获准参与的群聊由 AstrBot 完成模型选择、人格与历史、工具循环、流式生成、结果装饰与平台发送。V2 提供当前窗口获准的背景及原生工具，并在核心发送前应用窗口正文规则、语音策略、图片位置、组件排序、群引用/@和群分段，记录实际观测；不创建普通回复的 V2 batch、model round 或独立 OneBot 投递。

## 执行归属

| 阶段 | 当前实现 |
| --- | --- |
| 入站 | main.py 转发认领、对话开关、私聊权限及群参与检查。普通事件保留核心默认回复；显式关闭、拒绝、群旁听和私聊收尾仍安静。 |
| 原生会话 | 用正式 conversation manager 建立首次会话，冻结账号、窗口、当前人格与 conversation ID；实际重置或切换在后续调用前重新核对。 |
| 背景 | astrbot_host/core_reply_context.py 按领域读取本地资料，逐节降级，不调用模型或网络。私聊可读取关系、记忆、生活与主动灵感；群聊只读取群公开资料。两者通过 knowledge owner 读取窗口可用的本地知识和已归属成员描述，官方知识库仍由 AstrBot 原生回复链处理。 |
| 模型请求 | on_llm_request 先注入固定拟人/感知策略及当前角色的稳定档案、表达设置，再注入工具和真实发送工具，最后将本轮背景、时间/日历、群参与提示、分段和模型路由事实合并成一个 AstrBot `TextPart` 用户内容块并标记为仅本轮使用。AstrBot 已构造的人格与历史不重复注入，动态事实不改写系统提示词，也不要求旧 JSON 输出合同。 |
| 工具 | V2 工具并入本轮 ToolSet，调用真实领域 owner；AstrBot 管理工具循环及图片缓存。写操作以实际 native tool call ID 归属与去重，不虚构回复批次。 |
| 结果与发送 | AstrBot 原生装饰与发送保留。群文字在 event.send 前补用当前群窗口分段与间隔，宿主已分段时保留其边界；QQ 缓冲或增量流使用完整原生消息链逐段发送。V2 在真实外部调用前复核身份/权限；普通 event.send、原生流式及 send_message_to_user 都覆盖。 |
| 后台记录 | 原生输入、生成输出和发送返回分别记录。观察队列处理持久化、记忆与日记材料；记录或统计失败不阻塞核心回复。 |

call_llm=True 在当前 SDK 的含义是禁止默认模型阶段，因此普通事件不设置该字段。获准聊天通过核心 wake 标记进入默认流程。

群聊提及事实从原生消息组件和 QQ 官方提及标签采集，随本轮准入传入 Laya、群聊参与提示及工具续轮。QQ 官方消息有可核对的原始正文时，在原位置将本 Bot 的提及替换为 `<提及自己>`，其他提及标签保留原文；旧版缺少原文时按原生组件回退，不推测缺失位置。该标记固定指接收消息的 Bot，不指发言者。被提及允许进入处理且不归类为主动插话，但不代表必须回答；模型结合完整句意区分回答者、听众与被谈论对象，仍可选择旁听。

群观察和模型当前正文保留提及位置；恢复的当前正文通过 AstrBot 正常请求进入工具续轮和会话历史，不依赖临时感知块。只匹配宿主原始纯文本及已配置的前缀变换，不覆盖其他插件的自定义请求或合并后的新正文。后台记忆输入仍只保留 Plain 文本，过滤不会改变提及事实；仅提及的判断使用包含媒体和引用占位符的消息骨架。旧调用未提供原生事实时兼容 `<提及自己>` 与旧的规范化提及标记。

主动联系、提醒和显式日程命令仍有独立 V2 执行任务；它们不作为普通聊天的候选备用发送通道。普通回复的模型路由与历史仍由 AstrBot 管理；V2 回复页中的文字、语音、图片位置与组件排序进入本轮快照，群引用与 @ 使用经验证的当前群消息和发言者身份，群文字使用当前窗口分段规则与间隔。旧 JSON 合同和其他发送项保留给原任务及兼容。

群聊参与状态锁定为 `skip` 后，插件在当前 runner 实例上结束本轮，不依赖宿主额外的静默结束接口，也不修改 AstrBot 文件或共享类。当前工具批次及获准的互动学习、反馈先执行完，由原生步骤写入完整的 assistant/tool 配对；随后插件设置正常完成状态、空最终正文并调用一次结束回调，不再请求模型。首轮开始钩子位于原生步骤内部，因此首轮旁听由下一次步骤入口直接收尾；若宿主已添加步数耗尽指令，仅清除这次收尾前追加的末尾指令。

工具批次内的新消息延迟到整批参与决策确定后再标记消费；旁听时保持未消费并释放，交由各自消息流程继续处理。本轮完整缓存且未发送的工具轮正文从草稿和会话历史中移除，工具调用、结果、推理及已有历史保留；已向下游逐片输出的内容不回写删除。正常回答、用户中断和工具错误保留原生流程，结束时恢复本轮实例包装。

## 原生工具与媒体

日历、成长、关系、记忆、熟人、天气、当前发言证据和群记忆按当前权限发布。Image、Screen、Reality camera、Content、表情与群黑话通过原生工具桥读取或执行；执行端口按调用独立附着，不启动旧回复 supervisor。七项伴侣能力属于 V2 本体内部模块。

作品创建和续写使用真实核心调用 ID，通过 V2 专用写作任务生成，再由内部 Content 服务保存固定版本或候选版本。原件读取和本地诊断接入核心私聊工具，保留原来源、身份、撤回及检查有效期；工具结果由核心继续组织回复。

当前 SDK 在工具执行之后才把 assistant tool call 写入 messages。因此在精确核验当前 event/run_context 的 runner 实例上透明包装工具分派，先冻结真实 response 的调用 ID，再委托原方法。参数重查也走 SDK 的原有过程。

生成图和表情原图作为 MCP ImageContent 返回，核心自行缓存、查看并决定是否发出。Image 编辑和蒙版在实际调用时读取本轮获准附图及引用原图；引用来源保留账号、窗口、消息和发送者，并复核撤回。表情使用量在实际图片发送返回后更新，候选或生成成功不代表已经发出。

核心 send_message_to_user 直接使用 Context.send_message。当前实现仅替换本轮 ToolSet 内的该工具，以每次调用的 Context 副本委托原工具的组件构建、路径解析、核心发送和去重，不修改共享 Context 或工具注册表。发送只限原会话；平台未找到为已知失败，异常为未知，同轮相同未知操作不重放。

## 视频理解的分工

普通聊天的视频由 AstrBot 核心管线处理，V2 不另建请求；V2 会把视频原生送入本轮回复请求：Gemini 类模型直接读取整段原视频，其他模型自动抽帧作为图片送入同一轮请求，不依赖外部视频插件。未安装外部扩展时核心仍能看到视频路径与元信息，并由 V2 完成上述转述或抽帧。

V2 独立任务的视频转述是另一条路，只服务主动联系与历史兼容：它在 `conversation/media/video/narration.py` 里用自己的提示词直接理解原视频，再把结果作为文本交给 V2 生成链。

两条路不共用同一请求。核心里视频是原生内容块，V2 任务里是本地转述文本，开关、提示词与用量因此分开统计；回复页的感知设置只解释这层区别，不改变 AstrBot 的媒体理解配置。

## 配置页

模型页的普通回复卡标记 execution_path=astrbot_core，只保存实际消费的对话附加提示。provider、fallback、timeout、输出上限、替换路由等在 AstrBot 当前会话中配置，V2 API 拒绝写入无效字段。

治理页提示词目录显示当前生效的附加提示、背景固定规则和运行时提示组成，不再显示旧普通回复 JSON 输出合同。人格编辑仍在 AstrBot；V2 补充资料与当前人格冲突时，以当前人格为准。

回复风格与拟人表达继续读取当前窗口设置，并可在提示词目录中编辑；拟人开关关闭时不注入该项。附加提示与风格读取不校验旧语音配置；群分段独立读取失败时保留宿主发送，不挡住核心请求。私聊在模型请求前还会执行确定性的收尾判断：当前消息只是道别、晚安、感谢或应声，且角色上一轮已经收尾时跳过默认回复；判断只读已授权原生对话和三个收尾配置，失败时继续普通回复。本轮上下文块只参与当前模型请求，不进入 AstrBot 会话历史，既可让角色感知当下，也避免每轮时间、路由和决策提示改变系统提示缓存前缀。感知块使用 SDK 实际消费的 `TextPart`，由 Provider 适配器测试确认可到达模型请求；固定解释规则仍留在系统提示缓存前缀。回复页和理解页标注各发送项的适用范围。群唤醒默认关闭答疑、相关词留空；基础候选成立后才进入 Laya，关闭答疑的私聊窗口不改变群窗口。诊断见 [群聊高频回复修复](GROUP_REPLY_WAKEUP_20261010.md)和[私聊收尾沉默](PRIVATE_CLOSING_GUARD_20261020.md)。

表达规则在这一路径上按轮换顺序注入前 `rules_per_turn` 条，并只把这批标识记为一次注入；原生提示在 Laya 判断之前封存，因此这里不做按意图挑选。按 Laya 意图从候选池中挑出“排在无关规则之后的那一条”属于 V2 独立回复生成链（`conversation/generation.py`），两条路径的计数口径一致：只有实际进入模型请求的规则，且只有确认送达后才加一。

## 治理统计

核心观测写入独立 astrbot_core_reply_observations，异步快照用 revision 防止乱序覆盖。它不预留模型预算，也不写入旧 model requests、reply batches 或平台回执。

| 读数 | 口径 |
| --- | --- |
| 角色总用量 | 核心普通回复 + 历史 V2 回复 + 插件附加任务，各计一次。对话合计是前两者的合计。 |
| Token | 真实 runner 可观测时逐请求记录 Provider 使用量，包括工具续轮；只取得汇总或最后响应时单独标示，不伪造调用次数。 |
| 参数重查 | 当前 SDK 的 skills-like 参数重查可能包含未公开的中间请求；标为部分观测，仅记录实际取得的末次响应。 |
| 费用 | 核心费用未提供，纯核心所有层级及 CSV 保持未知。混合来源只显示已计价小计。 |
| 缓存 | 只有 Provider 明确报告的缓存字段进入命中率与覆盖统计；SDK 默认 input_cached=0 不算实报。 |
| 缓存检测 | 比较真实 runner 请求或降级请求钩子的结构签名；仅保留哈希、数量和长度，不保存提示词、参数或回复正文。签名作用域随数据返回。 |
| 回复效率 | 核心首次/末次发送返回、模型阶段、TTFT 和工具耗时与历史平台送达指标分列。流式允许先发送后生成结束，时间线按真实时间排列；QQ 内部缓存流的首块时间不替代实际 event.send 的开始时间。 |
| 发送结果 | send_returned 仅表示核心发送调用正常返回，不宣称 QQ 客户端送达。已知未发、未知、拒绝和部分成功保留各自状态。 |

空流、空消息链、空白正文和只有工具/推理元数据的流不计为发送返回；纯图片等可发送媒体仍可计入。QQ 以 event.send 实现流式时按实际发送逐次记录，外层流不重复计数。

其他 AstrBot 会话与外部插件统计不并入当前角色预算。不同来源的合计与子项不能重复相加。

## 验证

使用 AstrBot 自带 Python，临时数据根与本地模型/平台替身，覆盖真实 Process/Decorate/Respond、ToolLoopAgentRunner、SendMessageToUserTool/Context、领域 owner、群权限、流式、工具往返、异步记录和治理页读写。原生适配器在 4.27 / 4.28 / 4.29 上逐版本核对，同一套宿主用例结果一致；版本号不参与加载决策，其他版本照常启动并只记一条未核对警告，真正的接口变化会以导入错误直接暴露。群聊旁听通过 `tests.test_core_reply_silent_completion` 在未修改的 AstrBot 上核对首轮与后续轮、步数上限、工具配对、新消息消费和真实历史保存入口。

交付先同步唯一小屋构建清单，再构建当前源码包，从新解压包检查宿主加载、停机、路由注销与定向回归。结果保存到本次交付目录；本地验证不等于真实 Provider 或 QQ 客户端验收。
