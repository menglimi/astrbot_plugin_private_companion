# WeChat Native 接入与能力边界

## 基线与通道

本次适配以陪伴插件 `8b3b45d7bccb3da0fa9752b312aa40f610f51498` 和 WeChat Native **0.3.12**（`499dc1f5ace7b3e693f7392db2b8a94f4cb13215`）源码为依据；合成宿主验证使用 AstrBot 4.29.4。旧版适配器不作为当前接口保证。

- 普通回复继续由 AstrBot 选择模型、人格、历史与工具，经过既有陪伴钩子后调用原 `WeChatNativeEvent.send`。不另建普通回复任务，不替换适配器事件。
- 主动联系、日程与后台消息保留现有授权、免打扰、人格复核和发送前检查，最终经 `Platform.send_by_session` 投递。不直接请求 Native HTTP、不调用其底层发送方法。
- 账号键使用 AstrBot 平台实例 ID。参与者仍是真实发送者 ID；群 ID、成员 ID、原生会话分别存放。`weixin_oc` 与 QQ 的身份命名空间不变，微信与 QQ 窗口不自动关联。
- 原生会话只由适配器自身的 `session_id`／`session_target` 校验；不截断、重编码或从昵称推导。账号替换后旧会话失效。

## 配置

1. 先按 WeChat Native 自身说明安装、连接账号，并配置私聊／群白名单、群回复模式和媒体开关。插件仅处理适配器交付的事件，不扩大群监听范围。
2. 在陪伴小屋的现有账号、人格、关系与权限入口选择微信平台实例，按原有方式授权联系人或群。群共享会话和按成员独立会话都使用适配器提供的标识。
3. 每个需要主动联系的微信用户先发送一条正常私聊消息。可信会话由现有会话目录及宿主上下文持久化；重启后恢复。缺少记录时报告 `host_native_session_unavailable`，不会把用户 ID 当发送地址。
4. 语音、图片、设备、手机配对和外部服务继续使用各自现有配置与权限。没有可信昵称时展示真实标识，不抓取全量通讯录。

## 功能对照

“复用”表示接入同一套已有能力，不代表真实设备或外部服务已完成验证。下面的平台能力依据 0.3.12 源码，真实账号已反馈私聊、群聊文字、图片和语音可收发；本地测试与实机反馈分别记录，未逐项实测的能力仍保留待验说明。

| 能力 | 适配方式与限制 | 本地验证范围 |
| --- | --- | --- |
| 私聊与群聊 | 复用人格、历史、连续输入、群授权／观察／参与、分段、表达与工具循环 | 原事件捕获、私聊会话分离、群共享／成员会话、跨账号、启动／重启与核心钩子 |
| 图片、表情素材 | 标准 Image 组件及适配器上传；QQ Face 明示为 `[QQ表情 ID]`，不伪造微信表情 | 合成 PNG 入站、出站及混合消息保留 |
| ASR、TTS | 使用宿主原有提供方；标准 Record、现有语音策略与音色／语种设置 | 合成 WAV 入站、TTS 回调和真实适配器上传；无真实识别／播放结论 |
| 引用、群提及 | 核心发送边界添加标准 Reply／At，真实成员与原事件交给适配器检查 | 不透明 ID、首段／短回复策略、成员资料核验、撤回与循环保护 |
| PDF 与附件 | 保留适配器原 PDF 文本注入与“读取附件／图片／语音／文档”流程 | 原 PDF 钩子保留、去重；解析服务与真实附件待验 |
| 关系、记忆、表达学习 | 复用已有领域服务；外部记忆摘要传真实用户与独立会话 | 原有回归与会话参数定向测试；不迁移实验数据 |
| 生活与主动联系 | 复用状态、睡眠、天气、日程、日记、梦境、纪念日、候选及复核 | 完整发送器、策略拒绝、未知回执不重发；外部天气／手机到达待验 |
| Content | 沿用创作工具与权限；文字／图片可经现有链路回传 | 注册与通用工具回归；生成的文件不等于可微信发送 |
| Image | 沿用生成、编辑、参考图与提供方路由 | 标准图片组件；真实生图服务待验 |
| Screen | 沿用识屏工具与本机屏幕授权 | 注册／现有回归；真实屏幕与识别服务待验 |
| Reality | 沿用设备网关、手机配对与授权；音频授权保留原生会话 | 本机合成授权与宿主回归；不操作真实设备 |
| Together | 原生房间绑定已有独立会话、设备及手机权限 | 既有原生房间回归；真实手机房间待验；旧 QQ 群转私发链接入口不冒充微信私发 |
| Game | 沿用游戏工具；私聊背景匹配真实参与者与原生会话 | 精确房间边界与原有游戏回归；QQ 数字账号持久浏览器身份不扩展到微信 |
| Live | 沿用直播工具、服务权限及显式聊天绑定 | 注册／现有回归；不把 QQ 自聊自动出口视为微信出口，真实直播待验 |
| 微信原生工具 | 保留历史、群资料、成员、提及、群昵称／改名和撤回的原事件及原权限 | 原生工具接收同一事件；未模拟宣称全部远端操作成功 |
| 管理与诊断 | 使用既有账号／群／联系人、授权、窗口配置、主动测试、发送记录与耗时 | 原生目录、页面同步及相关回归；不新增配置体系 |

普通文件／视频发送、QQ 戳一戳／QQ 空间等不由本次新增通道补齐；缺少平台承载能力时明确不可用。文件内容理解与文件发送分开验收。

## 回执、数据与回退

`send_by_session` 正常返回沿用既有 `delivered` 本地回执口径，只表示本次调用返回；`astrbot-session:*` 是本地引用，均不代表手机确认收到。异常发生在平台调用阶段时记为结果未知，不自动重试。发送前的权限／路由拒绝记为未发送。

不新增数据库表、公开通信接口或不可逆迁移。真实用户与会话使用现有 ScopeRef、会话目录和 runtime_metadata。先前实验数据不自动删除、改名或合并。

回退到不认识 `wechat_native` 的原版前，通过现有账号／绑定配置流程撤下新增微信绑定，保留原 QQ 绑定、配置备份与数据。不要在保留新微信绑定的情况下宣称旧版能够正常加载。隔离验证覆盖原版→适配版→按此配置流程回退原版→再次升级；QQ 会话、数据库表结构与保留数据须一致，微信会话在再次升级后可恢复。无需降级 AstrBot 或微信适配器。
