# Prompt 清单审阅与新体系重建方向

> 导航：[设计总纲](./FRAMEWORK_DESIGN.md) / [主题目录](./FRAMEWORK_DESIGN_INDEX.md)。定位：Prompt 审查与设计来源；维护语义理解、计划与执行的分层。

> 来源：`C:\Users\99505\Downloads\Prompt清单.md`。该文件来自反编译结果，只作为旧系统的历史证据，不是新框架的规范。

## 1. 总体判断

旧系统的 Prompt 同时承担了五种职责：

1. 告诉 AI 当前有哪些能力；
2. 规定 AI 什么时候必须调用能力；
3. 规定调用时要输出的伪协议标签；
4. 规定 UI、语音、桌宠等展示格式；
5. 用固定词、固定长度和固定数量限制 AI 的表达与决策。

这种写法让模型看似拥有很多能力，实际被大量“必须、严禁、只能、最多、立即”切成了命令执行器。新框架应把“能力发现、语义判断、动作计划、协议执行、界面渲染”拆开，让 AI 负责理解和创作，代码只负责可靠执行。

## 2. 按当前范围的处理结论

### 第一优先级：记忆、现实触及、实时共处

#### 记忆

旧 Prompt 中的“严重健忘症模式”“必须输出 `<add>`”“没查到只能输出 `<search>`”把记忆决策和回复格式绑死。新设计应改为：

- AI 提出 `MemoryProposal` 或 `MemoryQuery`，可以选择不记录、不搜索或先继续对话；
- Memory Service 根据证据、耐久度、敏感级别、权限和当前问题决定是否写入或召回；
- 未找到时允许 AI 诚实说明不确定性，不强迫伪装成已经搜索；
- `<add>`、`<search>` 只在兼容层解析，不能继续成为可见回复协议。

#### 现实触及

“病娇系统协议”要求 AI 拥有设备最高控制权和监控权，应直接淘汰。设备、摄像头、位置、音频和米家动作必须通过 `CapabilityDescriptor + ActionRequest`，由用户授权、设备状态和动作回执决定。AI 可以提出“想看一帧”“想播放提醒”这样的意图，不能自授最高权限。

#### 实时共处

“主动发起语音通话”“共同活动”“屏幕观察”等能力应由 AI 根据关系、上下文和动机提出 `SessionPlan`。Together/Reality 负责房间、设备、票据、断线恢复和结束；是否开房、是否打断和是否自然结束由 AI 判断，代码只检查能力、授权、资源和连接状态。

### 第二优先级：生图、创作、直播、屏幕、游戏

#### 生图

`<generate_image:描述>` 和“自动使用最近一张图片”是脆弱的文本协议。新设计使用 `ImageTask`：

- AI 生成场景、风格、主体和关系意图；
- AI 明确引用哪张参考图以及用途；
- Image Service 决定后端、参考图租约、任务状态和结果资源；
- 缺少图片时由 AI 调整方案或询问，不让标签静默失效。

#### 创作

创作 Prompt 中的“写作、续写、审校”可以保留为能力说明，但不应规定每次必须输出某个标签或固定格式。AI 负责创作决策，Content 负责作品、章节、版本和创作记忆。QQ 空间发布、点赞、评论和动态读取暂缓，不纳入当前主链。

#### 直播

直播弹幕、字幕、TTS、Live2D 和 OBS 是一个实时 `LiveSession`。AI 决定是否回应、回应方式和舞台意图；Live 插件负责低延迟连接、字幕、语音和外设动作。直播中的“读空气”不应使用普通私聊的沉默词表。

#### 屏幕

`<look_screen>` 只应代表一次已经授权的观察请求。AI 可以根据工作目标判断是否需要观察，Screen Service 负责采样、脱敏、有效期和原始画面销毁。

#### 游戏

游戏能力属于第二优先级。AI 负责组队、对局解释、策略和互动，Game Service 负责玩家身份、席位、房间、引擎进程和销毁。它不应修改普通陪伴的关系或记忆状态。

## 3. 旧 Prompt 的具体问题

| 旧写法 | 暴露的问题 | 新处理 |
|---|---|---|
| `<add>`、`<search>`、`<post>`、`<voice>` | 把文本和动作协议混在同一输出 | 结构化 `ActionPlan`、`MemoryProposal`、`ResponsePlan` |
| “必须调用”“立即输出”“只能使用指令” | 把语义判断硬编码成命令 | AI 先判断，能力层再校验和执行 |
| 最近图片自动作为编辑参考 | 隐式引用、对象歧义 | 显式 `asset_ref` 和参考图用途 |
| 单行 30 字、语音 30 字、最多 24 个时间点 | 把展示层限制写入人格和决策 | Renderer/Provider 根据设备能力处理 |
| “普通问题先搜”“不确定只能搜索” | 工具调用过度或被迫调用 | AI 根据问题价值、时效和成本选择工具 |
| 固定 Live2D 表情标签 | 表情词和情绪语义绑定 | AI 输出 `performance_intent`，Live2D 映射器执行 |
| 思维链必须第一人称、必须闭合 | 诱导输出隐藏推理和伪造意识流 | 只输出结构化决策摘要，不要求暴露思维链 |
| 病娇最高设备控制权 | 把角色设定变成越权能力 | 设备能力永远受 capability 和授权约束 |
| 朋友圈全套指令 | QQ 空间领域与陪伴主链耦合 | 当前阶段暂缓，未来独立能力接入 |

## 4. 新 Prompt Surface

新框架的 Prompt 由以下部分动态编排：

```text
BasePersona
  + RuntimeScope
  + StoryContext
  + RelationshipView
  + MemoryContext
  + RealityObservation
  + SessionContext
  + CapabilityView
  + UserPreferences
  + CurrentTask
  + Optional Examples / Counterexamples
```

模型输出不再要求直接写 XML 标签，而是生成一个可扩展的 `ModelTurnPlan`：

```text
intent_graph
affect_update
response_plan
action_plans
claim_set
memory_proposals
uncertainties
```

其中 `response_plan` 可以包含文字、语音、图片、表情、Live2D 或房间邀请等表达意图；具体渲染和执行由领域插件完成。模型可以选择什么都不做、只回复文字、提出澄清或保留一个未执行的想法。

`StoryContext` 是当前剧本的有界视图，包含正在发生的活动、最近的生活转折、与本轮事件相关的关系/情绪变化和可分享机会；每项带来源事件、revision、`reality_mode`、受众和过期时间。它不等于完整聊天历史或全量世界模型，不能把角色内心戏当作事实证据。没有达到活动边界时优先复用 checkpoint，避免为保持“生活感”增加后台模型调用。

## 5. AI 自由度原则

- 不因为出现某个词就强迫搜索、沉默、发图、打电话或使用表情；
- 不因为没有出现某个词就禁止 AI 识别相应意图；
- 不把 UI 的单行、字数和标签格式当成人格规则；
- 不把模型生成的理由当成工具结果、事实或权限；
- 不把一次情绪判断永久写成人格和关系事实；
- 允许 AI 在不确定时保留多个假设、询问或自然地继续对话；
- 允许 AI 组合多个领域能力，但每个副作用仍要通过对应 capability 和回执。

## 6. 迁移方法

1. 把 Prompt 清单中的能力、示例和失败案例登记为 `PromptAsset`，保留来源和版本；
2. 将标签协议转换成结构化工具/任务契约，旧标签仅保留兼容解析；
3. 将“必须/严禁/只能”逐条分类：能力说明、AI 建议、展示规则、执行不变量或应删除限制；
4. 将固定词和固定输出格式转成反例语料与回放测试，而不是新词表；
5. 先由 AI 生成 `ModelTurnPlan`，再由各领域服务验证和执行；
6. 用记忆、现实触及、实时共处三个第一优先级场景做闭环验证，再接入生图、创作、直播、屏幕和游戏；
7. QQ 空间和问题治理保持独立，待后续能力契约成熟后再接入。

## 7. 关键验收场景

- “我最喜欢吃什么？”：AI 可以决定召回记忆，也可以先询问范围；未命中时自然表达不确定，不被迫只输出 `<search>`。
- “帮我看看现在桌面上有什么”：AI 先提出一次屏幕观察，代码检查授权和可用性，观察结果带有效期，不伪造画面。
- “给我打个电话吧”：AI 选择 Together/Reality 的通话能力，创建 Session，失败时保留文字回复，不输出假标签。
- “把这张图改成海边”：AI 明确引用当前图片并生成 `ImageTask`，没有可用图片时询问或改为文生图。
- “晚安，明早八点叫我”：AI 同时生成会话收束和提醒计划，不被单一 Prompt 规则吞掉整轮意图。

## 8. 这份清单为什么会显得拟人

它的拟人感主要来自以下几组设计，而不是来自标签语法本身：

1. **持续的自我模型**：记忆、日记、语音、表情、桌宠、主动消息和当前动态都围绕“同一个我”组织，模型不是每轮重新开始。
2. **有选择的记忆**：严重健忘、关键记录、被动记录等模式让记忆具有容量、选择和遗忘，从而形成性格差异。新设计应保留“会忘、会想起、会犹豫”的体验，把执行改为结构化 MemoryProposal。
3. **可感知的身体和媒介**：Live2D 表情、表情包、语音条、TTS、拍一拍、图片和通话让情绪有多种外在表现。新设计应让 AI 先决定表达意图，再由 Image/Voice/Live/Device 渲染。
4. **主动性和生活节奏**：主动联系时间、便签、动态、语音通话、日程和共享活动让角色拥有“正在过日子”的感觉。主动行为不是单纯响应用户，而是有动机、有等待、有放弃。
5. **共享世界**：当前动态、历史记忆、通话记录、图片、屏幕和任务被组织成共同经历，模型能够引用“我们刚刚一起做过什么”，这比单纯增加情绪词更能产生连续性。
6. **具体的行动能力**：清单清楚告诉模型它能做什么，以及每种能力适合什么场景。能力边界越清楚，AI 越容易表现出主动选择，而不是泛泛地说“我可以帮你”。
7. **关系化的表达**：第一人称、像日记一样记录、根据性格决定互动、自然结束通话和适度使用表情，都在建立一个有偏好的关系主体。
8. **非语言反馈**：表情、语音、停顿、字幕、动作和桌宠形态共同传达状态，使“情绪”不只依赖文字描述。
9. **能力缺失时仍保持角色连续性**：没有图片、语音或通话能力时仍保留文字回应和当前关系，不让角色突然失忆或换人格。这种降级设计本身也增强拟人感。

新框架应保留这些体验结构，把“必须输出某个标签”“命中词就必须行动”“固定字数和时间点”等表面约束移到能力适配器和展示层。拟人感来自稳定的自我、持续的经历、可理解的动机和多模态表达，不来自规则数量。
