# 爱语记忆机制评审与吸收方案

> 导航：[设计总纲](./FRAMEWORK_DESIGN.md) / [主题目录](./FRAMEWORK_DESIGN_INDEX.md)。定位：外部调研依据；吸收结论由记忆契约和评估集维护。

## 1. 结论

从可恢复的 APK 资源、业务字符串和界面说明看，爱语的记忆体验好，主要不是因为某个特殊的“记忆提示词”，而是因为它把几个环节连成了闭环：

```text
对话消息
→ 即时记忆提议或待添加队列
→ 后台/前台总结形成长期记忆
→ 语义检索、时间范围和相似度筛选
→ 稳定的摘要前缀 + 最近对话注入
→ 回复或主动行为
→ 用户可编辑、置顶、删除、导入导出
```

这条链路同时解决了“记得住”“找得到”“接得上当前对话”和“用户敢于纠正”四件事，因此用户会感到它持续理解自己。

## 2. 能确认的证据

爱语主体业务类被 `SecShell` 加壳，`jadx/sources` 中没有可直接阅读的业务实现。因此下面区分“文件中明确写出的行为”和“根据字符串、配置项及界面推断出的内部流程”，不把推断当作源码事实。

### 上下文和写入分层

`apktool/res/layout/activity_context_settings.xml` 明确列出三种模式：

- **混合模式**：滚动上下文的自动总结 + 动态上下文的缓存命中优化；聊天中产生的记忆先进入“待添加”队列，等总结触发后再正式入库，保持请求前缀稳定。
- **动态上下文模式**：累积到设定轮数后总结旧消息，后续请求携带摘要和最近消息；支持最大范围、动态起始轮数、自定义总结提示词和静默总结。
- **滚动上下文模式**：固定窗口保留最近 N 轮；聊天时记忆立即入库，窗口随消息移动。

同一布局还说明可以调整“记忆系统提示词约束”来改变模型写入记忆的主动性。这说明写入策略至少有一层可调的 AI 判断，而不是全部由数据库逻辑决定。

### 记忆库治理

业务字符串和 `activity_memory_manage.xml` 显示记忆库分为“置顶记忆 / 普通记忆 / 待添加的记忆”，支持搜索、相似度阈值、倒序、多选删除、置顶、编辑、导入和导出。日志还区分“已成功收集记忆”和“已成功添加记忆”，可确认存在“模型提出/收集”和“正式入库”的两阶段语义。

### 检索和上下文注入

可恢复的配置键包括记忆搜索相似度、最近 N 天时间限制、是否提供完整记忆、动态上下文起始轮数、总结触发轮数、最大动态范围、混合上下文保留前缀范围等。字符串还显示检索结果会以 system 消息注入，并可让工具调用链继续使用；多 persona 具有独立记忆库。

字符串中还能看到摘要完成、外部访问摘要完成和主动数据的扩展动作。这说明原产品已经在用事件把“摘要”“外部访问”“主动联系”串起来，但不能据此推断“写入一条记忆就必然主动联系”。新体系应让 Memory Writer 只发布记忆变更事件，由 Proactive Planner 根据冷却、边界、关系和资源预算另行决定是否产生主动候选。

## 3. 为什么会感觉“记忆很好”

### 即时路径和延迟路径并存

明确说出的偏好、身份或承诺可以快速进入收集流程；长对话则由总结任务压缩旧消息。即时路径降低“刚说完就忘”的落差，延迟路径避免每条消息都改变上下文前缀和长期库。

### 摘要与近期原文组合

只保留摘要会丢失当前语气，只保留窗口又会快速遗忘早期事实。动态/混合模式将历史摘要和最近若干轮并置，兼顾长期连续性和当前话题。

### 稳定前缀改善连续性

混合模式刻意让请求前缀保持稳定以提高缓存命中。缓存本身不产生记忆，但它减少了上下文结构抖动，使模型每轮接收的“自己是谁、记得什么”更一致，主观体验会更连贯。

### 检索有边界且可调

相似度阈值、时间范围、是否提供完整记忆和按相关度排序，构成了一个可控的查询层。模型不必每次面对全部历史，只接收与当前目的有关的片段。

### 用户拥有记忆主权

置顶、编辑、删除、导入导出和待添加列表让用户能修正系统。可见的治理入口会提高信任，也能阻止错误事实长期污染后续对话。

### 后台维护不打断对话

退出、后台或达到摘要边界时再处理旧消息，配合静默总结和失败重试，能把维护成本从对话体验中隐藏起来。新实现应把这部分做成可恢复的 `TaskEnvelope`，而不是在回复链中插入不可控的同步步骤。

## 4. 需要吸收的部分

这些机制应映射到新体系的开放契约，而不是照搬界面上的固定词或固定轮数。

| 爱语机制 | 新体系吸收方式 |
| --- | --- |
| 即时添加 + 待添加队列 | `MemoryProposal` 支持 `retention` 和 `defer_until_boundary`；Writer 负责幂等提交、重试和死信 |
| 动态总结旧上下文 | `TaskEnvelope(kind=memory_compaction)`，由 AI 决定摘要边界和需保留的事实，代码只执行预算与游标 |
| 摘要 + 最近消息 | 生成 `ContextContribution`，声明来源、有效期、用途和优先级；由上下文编排器合并 |
| 相似度/时间/完整记忆选项 | `MemoryQuery` 的语义查询、时间范围、允许的保留级别和结果上限；阈值属于运行配置，不属于人格规则 |
| 普通/置顶/待添加 | `MemoryAtom.status` 与 `retention=protected`；待添加保持独立状态，不能被当作已确认事实 |
| 收集成功/入库成功 | 分别记录 `memory_proposed` 和 `memory_committed` 事件，便于审计和失败重试 |
| 多 persona 独立库 | `RuntimeScope.persona_id` 作为强制作用域；跨客户端同步只能携带被授权的作用域 |
| 手动编辑、删除、导入导出 | 统一转成 `MemoryCorrection` 或受控批量导入任务，保留来源和版本，不直接改写历史 |
| 静默总结 | 后台任务只产出结构化事件和状态，是否通知用户交给 `ResponsePlan`，不改变事实写入规则 |

## 5. 明确舍弃的硬编码

反编译提示词中出现了“严重健忘症”、触发词、`<add:内容>`、`<search:关键词>`、去掉“什么/谁/哪里/怎么”等疑问词、每条消息必须添加记忆等规则。这些规则可能让演示看起来稳定，却会造成误记和协议泄漏：

- 关键词命中无法可靠处理否定、引用、反话、条件和多意图；
- 强制每条消息写入会把寒暄和一次性情绪变成噪声；
- 可见标签把内部工具协议暴露给用户；
- 禁止说“不知道/忘了”会诱导模型在检索失败时编造；
- 固定 N/Y/Z 轮数是资源策略，不应被写成角色行为；
- “第一人称脑内记忆”可以作为表达风格，不能代替证据、作用域和有效期。
- 全量记忆注入和外部同步需要经过作用域与隐私授权；否则上下文膨胀或跨端泄漏会抵消记忆优势。
- 手动编辑不能丢掉原始证据链；编辑应产生版本和 `MemoryCorrection`，而不是无来源地覆盖文本。

新体系改为：AI 先输出 `MemoryProposal` 或 `MemoryQuery`，解析器处理结构化协议；运行时代码只校验证据、作用域、生命周期、预算、幂等和投递结果。检索不到时允许返回不确定性，并把缺失证据显式传给回复规划器。

## 6. 新记忆闭环建议

```text
message_received
→ EvidenceRef 建立
→ AI 生成 IntentGraph
→ MemoryProposal(add/update/invalidate/no_op)
→ immediate commit 或 defer_until_boundary
→ MemoryQuery(reply/planning/proactive)
→ ContextContribution(摘要、事实、近期原文)
→ ResponsePlan / ActionPlan
→ DeliveryReceipt
→ 用户纠正或反馈
→ MemoryCorrection / 反馈事件
```

边界不再由“出现某个词”决定，而由 AI 对语义稳定性、时间条件、说话者和用户授权的判断决定。系统可以根据 `ResourceBudget`、上下文长度、缓存目标和失败恢复能力选择即时写入、延迟写入或只保留会话级记忆。

## 7. 第一批验收场景

1. 用户直接说“我下个月要搬到 B”，系统生成带时间范围的事实；旧地址仍可追溯，但不再作为当前地址使用。
2. 用户说“他说自己喜欢熬夜”，系统识别引用主体，不写入当前用户档案。
3. 用户说“我其实不喜欢咖啡，只是今天喝了一杯”，系统不把一次行为升级为偏好，并能修正旧的“喜欢咖啡”。
4. 用户在总结尚未完成时重启，待添加队列和游标只处理一次，失败任务可重试。
5. 用户要求忘记某条记忆，后续检索、摘要缓存和主动计划都不能重新带回该事实。
6. 检索无结果或证据过期时，回复可以表达不确定，不得凭空补全。
7. 未在预置词表中的新偏好仍能以开放的 `predicate/object` 保存和召回。

验收不能只看“能否回忆起显式偏好”。回放集至少应覆盖显式事实、跨轮隐含线索、否定/引用/反话/多意图，以及纠正/撤回/过期/跨作用域四组场景；指标同时观察召回率、准确率、时效性、冲突处理、误写率、重启幂等和用户可解释性。这样才能验证拟人连续感没有靠硬编码换来。

本评审与 [记忆契约 v0](MEMORY_CONTRACT_V0.md) 配套使用：爱语提供了值得借鉴的产品闭环，新契约负责去除其硬编码协议并补上证据、作用域和生命周期约束。
